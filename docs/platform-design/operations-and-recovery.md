# 运行、授权、资源生命周期与恢复

> **状态：长期原则 + 有界本机实现。** 本地 / 源码 / 组件声明切片之外，[Issue #12 运行切片](../development/mysql-runtime-slice.md)提供固定 MySQL 的同库受理、执行围栏、实际认证、观测与保留数据恢复。其余服务部署、SSE、AI、备份和物理清理仍为目标；本文推荐值由各实现组合验证固定，不能据设计文字直接授权运维。

## 期望态、实际态与持久操作

平台元数据库保存已接受的期望态与待处理操作；Docker、服务 Git 仓库和业务数据库保存各自边界内的事实。画布编辑和接受部署目标可在元数据库内原子提交，**不建立跨 Git、平台数据库、业务数据库与 Docker 的完整事务**。

每次部署或资源操作记录稳定操作 ID、项目与资源归属、目标代次、请求摘要、执行阶段、已产生的资源身份、步骤结果、尝试次数、执行代次 / 租约、下次重试时间及安全诊断。对外状态至少表达已受理、执行中、等待重试、需人工处理、成功、失败、取消和已被新目标替代；状态与步骤均持久化，可通过查询恢复，不能只存在内存或日志中。

1. 接受目标时，在同一平台数据库事务内保存不可变目标、待处理记录与事件；提交后由后台扫描 / 调和领取，通知丢失也不丢任务。
2. 后台按持久条件更新领取并携带执行代次，外部 I/O 不跨越长期数据库事务。推荐首版本机按项目串行改变运行资源，读取与分析可并行；业务正确性不依赖单一进程内锁。
3. 每个外部步骤先核对目标仍有效，再按稳定资源身份和操作 ID 查询 / 执行；成功后记录实际结果。暂时性故障有界退避并加入抖动；权限、配置、兼容性等确定性错误转入失败或人工处理，不无限重试。
4. 平台重启后接续未终结操作，核查外部实际状态后决定重试。Docker 已创建容器或 GitHub 已创建仓库而响应丢失时，先核实已有结果；不能改键、改名再创建。
5. 新目标取代旧目标后，旧执行器不得写入当前成功状态、切换当前版本或清理新资源；写入使用目标与执行代次条件。Docker 等未提供事务性隔离的边界还需适配器串行、资源代次隔离与再次对账，不能只靠一次执行前检查保证外部动作绝不迟到。

旧步骤可能已经产生副作用：按其原资源归属记录并展示，由当前调和器清理或吸收已有结果。补偿是新的有记录步骤，只处理确认归属且允许撤销的资源；不无条件倒序执行所有命令，不擅自删除数据库卷、源码或已经完成的业务写入。

用户取消后停止新步骤，当前在途步骤须先核实结果；「取消请求已收到」不等于外部副作用已回滚。无法安全自动判断的结果进入人工处理，展示已完成项、剩余资源和恢复动作。

## 持久操作状态转换

下列是首批实现应遵守的逻辑转换，状态线格式和稳定错误码在机器契约发布时固定。取消请求、替代原因和步骤的「结果未知」单独记录，不用一个终态掩盖在途副作用。

| 当前状态与刺激 | 允许的后续状态 | 前置条件与必须保留的结果 |
| --- | --- | --- |
| 新目标已持久受理 | 已受理 → 执行中 | 领取仍有效的目标，取得持久租约 / 执行代次，核对动作授权和资源身份 |
| 执行中遇暂时故障 | 等待重试 | 记录当前步骤与已知 / 未知结果、尝试次数和下次时间；未知副作用先查询，不直接再执行 |
| 重试时间到或平台重启 | 等待重试 / 执行中 → 执行中 | 核实当前目标、租约与外部结果，按条件领取；不能仅因旧租约到期就假定原外部动作已停止 |
| 执行步骤无法安全判定、重试耗尽或需要接受处置 | 需人工处理 | 保留资源、原因、已完成 / 未知项及允许的核实 / 接续 / 放弃入口，不自动破坏数据 |
| 确定性非法配置、权限或兼容问题且结果已核实 | 失败 | 明确原因及原结果，旧运行版本和部分成功资源仍可见；若还有未知副作用先进入需人工处理 |
| 全部必需步骤与整体就绪验证成功 | 成功 | 当前目标 / 执行代次仍匹配，实际镜像 / 配置 / 迁移符合清单且近期观测已持久化 |
| 用户请求取消 | 记录取消标记，核实后取消或需人工处理 | 停止领取新执行步骤；核实已发出动作，保留或登记后续清理，不声称自动回滚 |
| 新目标被接受 | 旧操作已被新目标替代 | 旧执行器停止推进当前目标；在途结果继续挂原操作，交由当前调和或独立恢复记录核实，不清理新资源 |
| 人工选择接续需处理操作 | 需人工处理 → 执行中 | 明确处置、现目标与原意图未变、权限有效、未知项已达到可安全接续条件；重新领取执行代次并留接受记录 |
| 重放成功 / 失败 / 取消 / 已替代的请求 | 返回原终态 | 不重开同一操作。显式重试或恢复创建关联原记录的新请求；目标未变可复用目标代次，内容变化须重新审阅 / 接受 |

步骤至少区分未开始、执行中、结果未知、成功、失败和按计划跳过，并保存输入摘要与外部身份。平台崩溃后的「执行中」先按未知结果核实，不能一律改成失败或直接重跑；已成功步骤只在事实不再成立时启动新的纠正步骤，不能因为 UI 重连而重复执行。

幂等重放先查原键和内容、再按当前权限返回原结果；历史记录过期后不自动换键复制副作用。项目内资源写入串行、执行代次条件与外部资源归属共同保护旧任务，不能由进程内锁代替。迁移 / 已提交业务写入等不可直接撤回动作的取消边界见[MySQL 运行契约](standard-middleware.md#初始化账号与迁移责任)。

## 收敛与状态真实性

调和持续比较当前目标、已登记资源与实际观测。运行资源由平台操作和登记；发现外部手工改动时明确标为漂移，不能静默当作用户接受的新期望态。推荐先采用保留现场并提示的策略，自动纠正范围需由产品策略明确授权。

一次部署的成功条件是：所需资源已按目标准备、数据库迁移成功、服务达到该切片定义的就绪条件、实际版本与目标清单一致，并已记录近期观测。容器进程运行、请求返回 202 或某个步骤成功都不等于整体成功。成功表示该次验收时刻成立，之后仍可能发生漂移和故障。

状态至少区分运行、健康、就绪、观测未知 / 过期和与目标不一致。失败或断开时保留最后观测与时间，不能继续以旧绿色标记宣称实时健康。SSE 的断线重放、完整快照和版本分离见[契约设计](canvas-contracts.md)。

## 自动恢复与外部漂移边界

首版建议将授权内操作恢复、运行故障和外部漂移分开处理：

| 事件 | 建议行为 |
| --- | --- |
| 平台进程重启 / 元数据库恢复连接 | 先恢复观测与资源对账，再接续仍有效的已授权操作；只关闭网页或 SSE 不取消后台持久操作 |
| 正常关闭平台控制面 | 停止领取新步骤、持久化进度并释放租约；已部署业务容器默认继续运行，另行「停止项目」才改变业务运行目标。平台自身 MySQL 的关闭与业务库分开，不隐含清理卷 |
| 业务进程意外退出 | 运行方案可明确配置 Docker 进程重启策略；首版建议运行目标使用 `unless-stopped`，只处理进程重启，不授予改配置、建新卷或回退数据权限；实际行为需 Compose 故障验证 |
| 用户通过平台停止项目 / 服务 | 先接受停止目标，再停止运行资源；调和和 Docker 重启策略不得绕过停止目标。目标保存失败时不先停止后假装已接受 |
| 用户在 Docker 等外部工具手工停止、删除或改配置 | 登记漂移并保留现场，不自动重建 / 接管或改写目标；用户选择重新应用固定目标、停止目标或形成新的显式变更后继续 |
| Docker 不可达或状态采集失败 | 保留最后观测与时间并标未知 / 过期，不能推断资源已经停止或已经删除；恢复可达后先查询 |

可观测事实不足以区分崩溃、外部修改或资源替换时，按未知 / 漂移处理，不猜测用户意图。自动修复漂移、整机重启后自动启动平台与更复杂重启策略仍需明确策略；首版建议值不代表本轮启用任何运行行为。重启策略的取值和边界参考 [Docker 官方说明](https://docs.docker.com/engine/containers/start-containers-automatically/)，不能把 Docker 进程重启与平台重建资源混为一项授权。

## 本机首次启动与应用访问

平台需提供统一且可重复的启动、停止、状态与诊断入口；具体命令随真实工程初始化后登记，不提前编造可运行命令。

- 启动预检核对工具链兼容、Docker 可达、工作区读写、磁盘空间、端口、配置与凭据可用性；失败指出具体项目 / 阶段和可操作原因，不自动安装或升级用户环境。
- 工作区根目录由用户设置或接受明确默认值后持久化，源码、元数据与业务数据位置可查询；路径不充当项目或仓库跨环境身份。实际默认位置仍待确定。
- 平台自用 MySQL 就绪后才初始化 / 迁移平台元数据，再开放可写控制面；平台迁移由既定 golang-migrate 管理，不把业务库迁移混入平台 schema。重复启动不得重复初始化或改写已应用迁移；不兼容或失败时停止相关写入，保留诊断与人工恢复入口。
- 项目 MySQL 健康检查通过后执行相应服务仓库的业务迁移，成功才将依赖服务标为可用。应用运行期还需有数据库断连、重连、超时与重试语义；结果未知的业务写入按契约幂等或查询核实，不盲重试。启动顺序不替代运行期容错。
- 推荐控制面、平台数据库和示例应用端口只绑定本机；端口冲突不得悄悄连接另一实例或擅自更改固定访问契约。若允许选择空闲端口，记录并回显实际地址。端口 / 代理与访问策略随切片固定。
- 部署完成展示已核实的应用入口、所属项目与服务，入口来自实际部署信息。停止平台或项目默认保留源码和数据，不把 `down -v` 当普通停止行为。

平台本地工作路径不依赖 GitHub 账号；完整无网启动、依赖安装、镜像缓存和离线 AI 的支持范围仍须单独决策。Todo 是独立示例项目，不是平台自身启动的必备业务。

## 本机控制面与凭据

**用户决定：一期不开发或接入账号、登录、配对、会话和 RBAC，只预留未来边界。** 当前仅支持单可信 OS 用户本机工具，保留回环监听、确切 Host / Origin、JSON 标记、路径允许范围与安全错误，不宣称这些措施构成账号认证。见[本地切片](../development/local-project-slice.md)。未来远程或多用户能力启用前再接入成熟身份机制。

未来身份接入时，读画布、改配置、修改文件、执行检查、运行资源、删除数据与外部发布分别判权；GUI、agents 和其他客户端共用授权与领域入口。连接订阅和长任务在权限撤销后停止后续受限访问，不只在页面打开时检查。

凭据只存受控秘密存储，平台元数据仅保存引用与状态。推荐 macOS 使用系统凭据库，其他系统采用对应安全适配器；不可用时明确说明并阻止依赖能力，不静默回退为普通明文文件。凭据由受信执行器按用途最小化注入，不进入 Git、画布、前端应用代码、普通 API / SSE、日志、AI 上下文或检查报告；执行器也不得在命令行或诊断中泄露。

创建 / 接入、轮换、撤销和删除凭据分开记录。撤销后停止新注入，对已在运行进程中的凭据按该服务声明的刷新 / 重启 / 替换模型处理，不能只改配置标记就称已失效。现有环境变量注入方式可保留，长期秘密的安全保存与日志脱敏由适配器承担。

## 首版本机初始化与认证建议

**以下认证、配对与凭据库方案保留为未来提案，不是一期前置，也未实现。** 当前采用环境注入和平台库 Compose，启动见[根 README](../../README.md)。以下不替用户选择业务技术栈。推荐 Go 控制服务以当前用户的宿主进程运行，读取 macOS 系统凭据库并调用受信 Docker 适配器；前端构建产物由它同源提供，平台自用 MySQL 由独立 Compose 单元提供。业务项目各有网络 / 卷，与平台元数据库隔离。开发态 Vite 只代理到同一受控 API，不通过全开放 CORS 绕过认证。

1. **本机引导**：启动入口先取得单实例锁，核对工作区 / 工具 / 端口 / Docker / 凭据库，生成或读取安装身份与平台数据库秘密；身份引用和非敏感位置保存在受限本机配置。无匹配配置但发现已有数据库 / 数据目录时停止并提供接入或恢复方案，不另建空环境冒充原实例。
2. **平台库初始化**：受信适配器将管理 / 运行所需秘密按用途注入平台 MySQL，并核对实例身份、健康与 schema。golang-migrate 完成后再开放可写控制面；失败保留数据与安全诊断。引导身份和秘密存储不依赖尚未就绪的元数据库，避免用用户尚无法访问的网页完成启动前置步骤。
3. **首次配对**：静态外壳和最小健康信息可以未认证读取，项目、文件、运行详情及所有写入都需会话。本机启动入口在受信本机界面显示一次性短效随机配对码，用户在指定同源配对页提交；不放进 URL、普通日志或 AI 上下文。配对端校验确切 Host / Origin、JSON 与必要请求头、有效期、单次消费和有界失败次数；失败不变成可远程初始化的入口。
4. **会话运输**：推荐首版使用成熟会话组件签发短期不透明凭证，服务端保存可撤销记录 / 摘要，浏览器仅存于当前页面内存并通过授权头发给控制 API。SSE 采用可携带授权头的 fetch 流并按游标恢复，不将凭证放查询参数；不以普通跨端口共享 cookie 或浏览器持久存储承载管理凭证。刷新 / 关闭页面后重新本机确认取得会话，是此建议方案的明确限制；若需要长期登录，再单独设计经过验证的安全会话方案。
5. **请求与应用隔离**：只有确切控制台 origin 获准，浏览器写接口拒绝空 / 非预期 Origin、简单表单内容与跨站请求；原生客户端 / agents 使用独立受控签发、限定用途的凭证类型，不靠缺少 Origin 自动当作可信。业务应用使用单独的 loopback 端口 / origin，控制服务不把任意业务 HTML 或脚本托管为控制台内容，也不把授权头转发给应用。授权头只发给解析后匹配的控制 API URL，重定向或外链不能携带管理凭证。
6. **失效与撤销**：到期 / 注销 / 本机撤销后 API 返回身份失效，关闭相应 SSE、轮询和后续受限动作；重连后重新取得快照与现权限。后台任务依其持久动作授权决定能否继续，权限被撤销则停止新受限步骤、核实在途结果，不把网页关闭等同撤销已批准部署。

此方案仍依赖控制台防 XSS：文件、日志和模型文本只按数据呈现，前端不能执行业务仓库 HTML / 脚本，页面不加载不必要第三方脚本。CSRF 防护、会话组件 / 生命周期和浏览器请求行为必须真实验证，不能仅凭 loopback、CORS 或 SameSite 声称安全。[OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)、[会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

第三方长期凭据推荐通过受信本机设置 / 凭据库入口配置，控制台仅显示引用与可用状态；若实现浏览器录入，必须单独限定一次性秘密写入口与授权，禁止读回、持久缓存、请求体日志和转发 AI。业务服务、数据库账号和运行文件的最小化注入按[中间件契约](standard-middleware.md#首个-mysql-定义与连接)执行。跨用户、远程控制面、证书部署和其他操作系统的引导方式不由此方案自动覆盖。

启动、端口和代理已在[根 README](../../README.md)登记；安装包、会话库、凭据库和身份生命周期为未来提案。允许根须显式配置。

## 停止、移除与删除

| 用户动作 | 运行与平台记录 | 源码与持久数据 |
| --- | --- | --- |
| 停止项目 / 服务 | 接受明确的停止目标，停止所拥有的运行实例；调和器不会马上将其重启 | 默认保留仓库、未提交文件、数据库卷及历史 |
| 从画布移除服务 | 原子移除声明与连线；接受部署变更后按操作记录停止 / 清理平台拥有的运行资源 | 默认保留对应仓库和卷，展示保留位置；不将未处理容器隐匿为「已删除」 |
| 删除项目 | 进入删除中并关闭新写入 / 新任务，逐项清理获准运行资源，核实后才标记删除完成 | 推荐默认保留源码和持久数据，列明保留项与后续独立清理入口 |
| 删除源码 / 删除业务数据 | 分别列出具体仓库、工作区、卷、影响范围与不可恢复边界，执行明确选择的清理计划 | 不因停止或移除而隐含授权；未完成项和失败原因可见 |
| 断开 GitHub 远端 | 撤销平台关联或授权，不推送、不改写历史 | 默认保留本地仓库及远端仓库；删除远端是另一个显式动作 |

资源依据不可变项目 / 组件 / 资源身份与代次登记归属，删除前复查，不能仅凭可复用名称、目录名或容器前缀批量清理。共享中间件依据当前有效引用与所有者策略判断是否可释放，删除一个项目不能破坏其他项目。

删除操作也持久化步骤并可重试；Docker 离线、权限撤销或磁盘失败时展示「删除中 / 需处理」和残留清单，不提前抹掉唯一归属记录。删除完成的语义包括计划保留项已登记，而非声称所有文件均物理抹除。旧删除任务不得删除新建同名资源；若未来支持保留运行资源并移交管理，须先有显式归属转移，不能制造画布外未登记组件。

## AI 授权、隔离、预算与数据外发

AI 任务记录目标项目 / 服务、基准版本、适用规范快照、可用工具与路径、网络范围、凭据用途、外部动作许可、预算和取消状态。工程文档与 AGENTS.md 提供开发规则，不能自行扩大工具权限；加载机制见[项目规范](ai-development-standards.md)。

| 能力 | 授权与执行边界 |
| --- | --- |
| 只读分析 | 读取已授权项目范围与适用规范；选择文件不等于授权外发整个目录 |
| 编辑与测试 | 在任务工作区内形成候选修改，使用受控检查入口；测试和依赖脚本按不可信代码隔离 |
| 本地 Git commit | 独立许可，记录具体仓库、内容与检查；是否默认自动提交尚未决定 |
| push / 创建远端 / 部署 / 数据迁移 | 分别核对动作、目标与明确用户请求或已接受自动化策略；不从一般开发任务隐含推导发布授权 |
| 平台自身升级、清空平台数据 | 不属于业务开发 AI 的自主权限 |

推荐每任务使用独立分支与 worktree；执行器只挂载必要工作区及只读规范，不直接挂载用户主目录、SSH 私钥、宿主 Docker socket 或其他项目。worktree 解决源码并发，不是安全沙箱。构建和测试通过受限进程 / 容器执行，限制 CPU、内存、磁盘、进程、时长和网络；编排宿主资源由另一个受信适配器按受控请求执行。

选择外部模型前展示提供商和可能外发的源码、上下文、日志类别；实际输入按任务裁剪，推荐默认排除凭据、环境变量文件、数据库转储、`.git` 内部内容与未选择目录。脱敏与密钥扫描只能降低泄露风险，不能宣称绝对安全。数据外发许可、保存政策和联网能力与本地编辑许可分别记录，不静默切换提供商。

每任务设置可见且可配置的时长、模型调用 / 费用、重试和工具资源预算。到限停止新动作并保留候选产物，取消时终止可取消进程并核实在途外部结果。具体默认数值、预算追加和自动提交 / 发布策略仍待产品决定。

## 备份、恢复与保留

备份分别覆盖平台元数据与操作记录、服务 Git 历史及未提交文件、业务数据库和必要非敏感配置。镜像、构建产物与日志按可重建性和排障需要分类；凭据单独保护，默认不进入普通备份。GitHub 远端不包含未提交内容、平台记录或数据库，不能作为完整备份。

推荐一期提供手动备份、升级前备份和恢复预览，后续再按保留策略自动化。数据库使用经验证的一致性备份 / 受控快照，不直接复制运行中的数据库卷并宣称可靠。跨边界备份清单记录各自时间、版本、源码未提交状态和摘要；需要同一恢复点时须协调暂停写入或提供等价方案，不声称各自独立备份天然构成跨系统一致快照。

恢复先验证备份完整性、格式 / schema、迁移与工具兼容，在新位置恢复并核验再显式切换，默认不覆盖现有数据。恢复后先冻结副作用，核对目标机器、Docker 资源、凭据引用与旧操作结果，再解除调和、清理和外部写入；不能因为恢复了旧任务表就重复部署或删除当前资源。

定期演练恢复并记录结果。备份频率、保留期、加密 / 密钥恢复与备份目的地需产品决策；若要求应对整机损坏，必须有本机之外的副本，上传到远端需明确配置和数据外发授权。

## 构建、替换与数据库迁移

模板、规范、工具链和源码 commit 与检查证据绑定，构建产物记录镜像 digest、基底及迁移版本。构建一次，部署已检查的不可变产物；不能仅以分支名或可变 tag 标识已运行版本。详情见[服务工程](service-engineering.md)与[仓库追溯](service-repositories.md)。

零感知替换在后续切片开放：先准备新实例并验证就绪，再切流，最后排空旧实例；失败恢复必须核实实际流量入口与版本。数据库迁移优先采用兼容新旧服务的扩展 / 收缩步骤，破坏性清理独立安排；应用镜像回退与数据库 / 消息数据恢复分开设计。迁移不兼容时不得承诺一键回滚或零感知升级。

这些要求不阻塞首个手写 Todo 验证闭环，但在开放真实替换、升级、破坏性数据操作或使用真实业务数据之前，必须具备相应验证和恢复入口。

## 分阶段故障验收

以下是未来实施的验收要求，**本轮没有运行这些产品测试**；实现时使用真实数据库 / Docker 边界验证关键状态，不以 mock 调用次数替代。

| 阶段与场景 | 应观察到的结果 |
| --- | --- |
| 首个闭环：启动缺少 Docker、端口被占或迁移失败 | 精确诊断、不误连其他实例、不进入假就绪，数据保留 |
| 首个闭环：Todo 操作后重启服务 / 平台 | 数据仍在项目 MySQL，目标与实际版本恢复可查；Todo 只是示例 |
| 首个闭环：数据库暂时断开再恢复 | 就绪与故障真实回显，恢复后业务可用，结果未知的写入按业务契约核实而非盲重试 |
| 首个闭环：容器创建成功但响应丢失、重复请求 | 相同操作身份核实原资源，无重复容器或卷 |
| 首个闭环：中间件成功、服务失败及平台执行中重启 | 记录部分成功、保留数据，接续 / 补偿 / 人工入口明确 |
| 首个闭环：新目标取代旧任务、旧结果迟到 | 不回退当前目标或误报新目标成功，旧资源仍可对账 |
| 首个闭环：SSE 重复、断连和游标过期 | 原键恢复、快照补齐，未保存草稿保留且状态过期可见 |
| 首个闭环：停止、移除与重复删除项目 | 默认保留源码与数据，清理仅针对确认归属运行资源；物理删除源码 / 业务数据在备份恢复就绪前不开启 |
| 首个闭环：固定 commit 登记、源码变动及构建 / 部署 | 运行镜像可查到独立仓库和 commit，不部署未检查源码，不依赖完整 Git UI |
| 首个闭环：MySQL schema、端口 / 绑定与账号权限 | 同版本前后端校验，非法关系不保存；合法关系生成可用配置，应用不能执行管理或跨库操作 |
| 未来身份接入：首次配对、刷新 / 注销 / 撤销与业务应用跨端口调用 | 配对短效单次，身份失效即拒绝；业务应用拿不到控制台凭证，SSE 恢复仍需当前授权 |
| 首个闭环：平台关闭、业务进程崩溃与外部手工停止 | 控制面关闭不隐含停止业务；停止目标不被自动重启，外部漂移与未知按表反馈 |
| 首个闭环：跨站网页调用本机写接口或凭据缺失 | 未授权动作拒绝，错误、日志和事件不泄露秘密 |
| 开放完整 Git / 编辑器 / AI：并发保存、外部 Git 操作与多文件应用中断 | 平台协调入口间冲突不覆盖；外部并发按明确边界暂停 / 核实，逐文件结果可查，旧证据失效 |
| 开放技术栈与 agents：规范缺失、离线或执行中升级 | 每服务实际读取固定适用规范，缺失则阻塞，升级不偷换任务依据 |
| 开放 AI：越权工具、预算到限与取消 | 权限由执行器拦截，停止新动作，在途结果可追溯 |
| 开放升级 / 真实数据：备份恢复到新位置 | 校验与试恢复成功，旧数据不覆盖，旧任务不自动产生副作用 |
| 开放替换：持续请求、新实例未就绪与迁移不兼容 | 切流 / 排空可验证，失败恢复真实，不用镜像回退冒充数据恢复 |
| 开放 GitHub：远端创建结果未知、已有初始历史或同步冲突 | 查询既有结果、保留历史，重试不重复创建、不强推覆盖 |

## 建议默认参数

以下仅为首个本机切片的工程初值，按真实资源规模验证后写入已版本化配置并在诊断中可查询，不表示用户已经决定所有数值。业务调用、迁移与模型预算分别声明，不能被平台请求超时一并取消。

| 参数 | 建议初值 | 到界行为与验证 |
| --- | --- | --- |
| 普通控制 API 客户端等待 | 10 秒；外部步骤异步受理 | 超时保留原键，查询持久结果；不据浏览器超时判部署失败 |
| 运行观测 | 5 秒采集；20 秒无成功采集标过期 | 显示最后采集时间与未知，资源多时验证负载并调整，不伪造健康 |
| SSE 心跳 / 无数据连接检查 | 15 秒 / 45 秒 | 检查重连并按原游标恢复，业务操作继续独立执行 |
| SSE 重放保留 | 每项目 24 小时且至多 100000 条，任一界限先到即裁剪 | 游标不在窗口就返回完整恢复信封，先推进到一致快照再接续事件 |
| 暂时性步骤重试 | 初次失败后最多 5 次；退避基数 1 秒、上限 30 秒并加抖动 | 每次先核实目标与未知结果；耗尽转需人工处理，人工可重新接受恢复动作 |
| 数据库启动 / 服务启动就绪等待 | 各 120 秒，按运行方案分别覆盖 | 到限保留诊断与已有资源；失败不得自动清库，迁移使用独立明确时限和结果核实 |
| 未来配对码 / 会话有效期（一期不实现） | 配对码 5 分钟、最多 5 次失败；会话空闲 30 分钟、绝对 8 小时 | 失效需本机重新确认；后台轮询不自动无限延长用户空闲期限，授权撤销即时生效 |
| 幂等结果可查询期 | 首版建议至少 7 天 | 已查询到的记录不重做；超期不自动换键复制副作用。未终结操作与唯一资源归属记录不得按该期限清除 |

请求 / 帧 / 快照大小、执行租约续期、磁盘阈值、工作区容量和日志保留在对应机器契约 / 运行方案中单独固定并测量；AI 费用预算和备份保留仍是产品决策，不从这些数值推导。参数升级保留版本与影响，不静默改变已有部署身份或历史结果。

## 推荐默认与待确认产品决策

工程原则、最小 Git 追溯与标准中间件 schema 方向已确认。MySQL 的显式文件适配、控制面退出后容器继续、明确停止保留数据、每项目串行 / 围栏，以及新鲜度 / 租约 / 重试初值已在运行切片具体化；不推导其他服务已经实现。平台配对与账号系统一期排除；AI、长期凭据库、备份恢复、物理清理和其他参数仍按对应切片验证，不由本设计额外授权运维。

以下仍待确认，不写成用户已决定：

- AI 是否可默认本地提交、push 或部署，以及自动化策略、审阅条件与预算默认值。
- 备份频率、保留期、目标设备 / 远端及恢复目标。
- 完整离线能力：安装、依赖与镜像获取、AI 提供商及断网时哪些操作可用。
- 首个业务组合已由用户确认为 Go + 标准库 `net/http`；兼容版本与模板在对应切片验证锁定，其他业务栈不从平台技术栈推导。
- 工作区默认位置、控制 / 应用端口、参数验证后的取值与实现库；本节已给新鲜度 / 重试 / 事件保留初值，不必全部交由用户逐项决定。外部漂移自动纠正范围、长期登录与整机开机启动策略仍须明确。
