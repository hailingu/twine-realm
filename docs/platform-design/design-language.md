## 品牌与视觉方向

视觉主题是**安静、精密的工程工作台**。以暖白页面、白色面板、近白画布、细灰线和深灰主要操作建立层次，用稳定的排版承载复杂系统关系。选中、业务健康、失败、草稿和版本差异各有独立语义，不用大面积高饱和颜色装饰画布。

图标与文案共同表达服务、中间件、仓库和状态。卡片以边框和背景层级划分，阴影仅用于浮层；服务健康不驱动整张卡片变绿，失败通过清晰的状态区与错误摘要呈现。品牌标志与最终字标仍待设计。

## 背景与线条规则

- 页面与画布采用接近纸面的浅色层次，面板用白底和 `1px` 中性边框分组；网格若存在只作辅助定位，不覆盖主要关系，不默认铺满高对比网格。
- 普通分隔线使用 `border.subtle`；输入边界、可交互端口和关键连接使用更清晰的专用 token。浅分隔线不能独自承担控件识别、焦点或状态编码。
- 线性图标以 `1.65px` 圆端点 / 圆转角作为候选。组件类型色可用于局部图标，但必须同时有类型名称；红色类型图标不代表服务失败。
- 关键连接拟采用 `1.5–2px`、不透明的 `edge.default`，在缩放后校验箭头与标签可读性。依赖实线、事件虚线及方向标签的原有规则保持；告警使用独立状态标记与文案，不改变线型原本的关系语义。
- 选中使用较深中性边框与标记；键盘焦点另用 `2px` 外环、`3px` 偏移，避免被选中或错误边框覆盖。异常可使用砖红边框与轻暖红底，健康与警告仍保留图标 / 文字。

## Token 与深浅主题策略

采用「基础值 → 语义 token → 组件状态」分层。页面与组件引用用途明确的 token，具体颜色在主题中映射；同一个语义在深浅主题下保持相同含义。以下全部是 **twine-realm 待验证候选值**，不代表主题或组件已经实现；浅色取自上述观察或为可读性加深，深色是同一暖灰色系的独立适配。

| 语义 token 示例 | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| `surface.page` | `#F5F5F4` | `#20201E` | 页面底色 |
| `surface.canvas` | `#FCFCFB` | `#232320` | 画布底色 |
| `surface.panel` | `#FFFFFF` | `#2B2B28` | 面板、卡片与表单 |
| `surface.selected` | `#F3F3F1` | `#393933` | 列表等选中区域的轻背景 |
| `border.subtle` | `#E5E5E3` | `#41413B` | 装饰性分组与分隔 |
| `border.interactive` | `#777772` | `#85857B` | 需要辨认的交互边界 |
| `text.primary` | `#292927` | `#EFEFEA` | 主要文字 |
| `text.secondary` | `#6A6A63` | `#B7B7AC` | 次级说明与时间，较参考页的浅灰字加深 |
| `brand.interactive` | `#353533` | `#E5E5DD` | 链接与交互强调；链接另有下划线或等价标记 |

草稿、运行版本与差异用明确文案和图形标记表达；可以复用中性色或品牌色，但不能占用成功 / 失败语义。按钮填充、文字、边框、禁用态与浮层需有各自的组件 token，不能直接拿表中的前景色充当任意背景。

深浅主题从设计阶段使用相同语义覆盖，以暖白浅色作为首个视觉基线；深色候选须另做原型与对比验证，不能视为参考页已有能力。主题选项仍拟为「跟随系统 / 深色 / 浅色」，默认跟随系统。切换主题只改变呈现，不改变状态含义、图结构或用户上下文。高对比模式保留系统可识别的焦点、边界与文字；主题功能尚未实现，不能宣称已经支持。

对不透明 sRGB 色对的初算发现：参考次级字 `#777772` 在页面底 `#F5F5F4` 上约 `4.13:1`，因此候选次级字改为 `#6A6A63`，在该底色上约 `4.99:1`；参考浅分隔线 `#E5E5E3` 与白底约 `1.26:1`，只作装饰分隔。候选关键连线 `#74746A` 与画布底约 `4.60:1`，白字与主要按钮底 `#343432` 约 `12.48:1`。

这些结果只覆盖指定色对，不等于产品已通过无障碍验证。组件各状态、透明叠加、深浅主题、焦点与选中同时出现、画布缩放和状态图标仍需在真实原型中验证；不得把低对比小点、浅线或淡字作为唯一信息载体。

## 字体、间距与密度

| 项目 | 候选规则 |
| --- | --- |
| 字体 | 优先系统无衬线字体与中文系统字形，不预置外部字体依赖；commit、路径、端口和日志使用系统等宽字体 |
| 字号与层级 | 正文 / 表单约 14 px，辅助信息约 12–13 px，面板标题约 16 px，页面标题约 20 px；避免用小字补救过密布局 |
| 间距 | 4 px 基础步长，主要内容使用 8 / 12 / 16 / 24 px；同类表单与节点保持一致 |
| 密度 | 默认清晰可读，表格可评估紧凑模式；行高与可操作区域分别考虑，密集数据不缩小焦点目标 |
| 形状与层级 | 节点与面板约 8 px 圆角，紧凑控件约 4 px；边框区分层级，浮层遮挡不掩盖关键运行状态 |
| 文案与数字 | 中文界面，技术专名保留；状态用具体动作与结果，时间与数值标明单位，截断的路径 / commit 可访问完整值 |

## 组件状态规则

每类交互组件都需描述默认、悬停、焦点、按下、选中、禁用、加载与错误等适用状态；业务状态与交互状态分别建模。

| 组件 | 规则提案 |
| --- | --- |
| 按钮 | 每个区域突出一个主要动作；加载时显示阶段，禁止重复提交；禁用原因在附近可读，不能只放在悬停提示里 |
| 输入与配置项 | 标签始终可见，提示用途与生效模型，错误与字段关联；敏感配置仅显示引用与是否已配置 |
| 页签与侧栏 | 选中状态与键盘焦点分别可见；切换与关闭后焦点有明确落点，未保存内容状态可见 |
| 状态标签 | 图标 / 形状 + 文字 + 可选颜色；「运行中」「健康」「待部署」「状态未知」互不替代 |
| 数据表与列表 | 提供命名、排序 / 筛选状态、选中与展开提示；错误、空结果、初次空状态和加载状态分开，不把没有数据显示成系统健康 |
| 变更与错误提示 | 说明所属服务、版本、阶段与恢复动作；关键失败留存在事件记录中，不只靠短暂通知 |

## 画布节点、端口与连线

| 对象 | twine-realm 规则提案 |
| --- | --- |
| 节点类型 | 业务服务与标准中间件采用不同类型图标和名称标签，统一卡片结构；不只靠底色区分类别 |
| 节点信息 | 标题、类型、草稿差异、运行状态区分层显示；服务源码仓库与 commit 在详情中展开，避免节点挤入长路径 |
| 选中与焦点 | 选中边框配合标记，键盘焦点使用独立外环；错误、选中和焦点可以同时辨认 |
| 端口 | 输入、输出、事件、依赖各有名称与方向；可连接 / 不兼容状态附原因，连接前后都能从列表中检查 |
| 连接语义 | 依赖使用实线，事件使用虚线并标箭头；标签说明事件名或读写用途。线型表示关系类型，不同时拿来表示健康状态 |
| 草稿差异 | 新增、修改、删除使用文字 / 图标标记；待删除连接仍可在审阅中辨认，不直接抹去正在运行的关系 |
| 实际运行 | 用独立状态标记与观测时间呈现；声明的连接不代表已有真实流量，缺少观测时不播放流量动画 |

上述节点与连线是服务端图模型的投影。画布与服务 / 连接列表共用同一选择、编辑和验证结果；拖拽预览不自行改写服务端真相。

组件定义版本、具名端口和关系校验见[契约设计](canvas-contracts.md)。线型和箭头按具体关系语义呈现，不能从业务事件方向推导启动顺序；运行未知、操作待重试和删除残留依[运行与恢复](operations-and-recovery.md)展示，与草稿选中态保持可辨认。

## 无障碍与动效

以下是实施与验收目标，尚无产品通过验证的结论。

- 所有主要任务提供键盘路径：从目录添加组件、通过服务 / 连接列表选择、用表单创建和删除连接、调整配置与进入审阅；拖拽不是唯一操作方式。
- 明确工作区焦点顺序与画布退出方式，提供跳转入口；关闭面板 / 对话框后返回触发位置，避免键盘焦点丢失或被画布困住。
- 普通文字以至少 4.5:1、大字号文字以至少 3:1、关键图形与交互边界以至少 3:1 的对比度作为目标；按两种主题及真实背景逐状态验证，不能用参考系统已达标来代替本产品检查。数值依据见[Fluent 2 无障碍指南](https://fluent2.microsoft.design/accessibility)。
- 服务与连接列表、表单和表格提供可读名称、关系、选中与错误状态；辅助技术能获取部署进度与失败摘要，避免把高频日志持续播报成干扰。
- 页面与文字放大时保留内容与操作。二维拓扑可保留独立平移区域，并通过可重排的列表 / 详情提供同等任务入口；实际缩放、窄屏、键盘与辅助技术效果需实测。
- 状态变化用文字和图形同步表达，颜色不是唯一编码。尊重减少动态效果偏好；拖拽和缩放反馈保持直接，避免装饰性闪烁、循环脉冲与整页入场动效。

后续评审须覆盖深浅主题、错误与禁用组合、键盘焦点、服务 / 连接列表替代操作、状态过期、长文本和页面缩放，再固化 token 与组件规格。本次只形成设计文档。
