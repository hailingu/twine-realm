# 工作台与页面布局设计

> **状态：待验证的设计提案，未实现。** 布局与交互服务于单用户本机、docker-compose 优先的目标；尺寸是设计起点，不是已落地规格。服务级 Git 方向见[仓库设计](service-repositories.md)，颜色与组件规则见[设计语言](design-language.md)。

## 页面职责与产品边界

twine-realm 以项目画布为工作中心，把组件编排、服务配置、代码仓库、变更审阅与部署追溯放在同一项目上下文中。页面分别呈现候选草稿、已接受的期望态与真实本机项目空间的观测结果；AI 工作流使用相同的版本与验证记录，便于用户从变更定位到运行结果。

| 页面 / 视图 | 用户任务 | 初期边界 |
| --- | --- | --- |
| 项目入口 | 查看项目与最近的真实状态，创建或打开画布 | 本机单用户，不引入团队与租户管理 |
| 项目工作台 | 编排组件、配置服务、查看运行状态、发起 AI 变更 | 主工作区，默认环境为本机；不预设多环境已实现 |
| 代码视图 | 查看项目 / 服务目录，多个标签阅读与编辑文本，与 AI 协作 | 服务工作区内的简单编辑器，文件保存与提交、部署分别处理 |
| 变更审阅 | 比较画布、配置和各服务源码变化，查看验证与部署计划 | 可从工作台展开；审阅记录绑定具体版本 |
| 部署与事件历史 | 追溯各服务 commit、测试、镜像与运行结果 | 与当前草稿分开展示，支持从故障定位到服务 |
| 项目设置 | 查看项目空间与工作区位置、项目级偏好 | Git 仓库配置归属具体服务；此处仅可汇总各服务的仓库状态 |

## 五区工作台

桌面布局以 1440 px 宽作为评审样例：顶部约 56 px、左栏约 240 px、右栏约 360 px、底部折叠栏约 32 px，其余空间优先留给画布。下图使用后续扩展场景表达区域关系，Todo 示例项目沿用相同布局。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 项目 / 本机环境   草稿版本 · 已保存   当前运行版本   保存 / 审阅与部署    │
├─────────────┬───────────────────────────────────┬──────────────────────┤
│ 组件目录    │ React Flow 画布                   │ 当前选中服务 / 连接  │
│ 搜索        │                                   │ 配置 · 运行 · AI     │
│ 业务服务    │ 订单服务 → RabbitMQ → 发券服务    │                      │
│ 标准中间件  │                         ↓         │ 仓库 / 配置 / 健康   │
│             │                       MySQL       │ 变更建议与验证证据   │
│ 服务/连接表 │ 缩放 · 适配 · 定位                │                      │
├─────────────┴───────────────────────────────────┴──────────────────────┤
│ 事件与日志  构建 / 测试 / 部署 / 运行  过滤 · 错误数 · 最近观测时间      │
└────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 内容与行为 |
| --- | --- |
| 顶部项目栏 | 项目与环境、草稿保存状态、草稿版本、已部署版本及实际观测偏差；「保存草稿」与「审阅与部署」分开，不把保存理解为上线 |
| 左侧组件目录 | 按业务服务、标准中间件分组；提供搜索、拖入和「添加」按钮。服务 / 连接列表是与画布同步的替代入口，不是第二份数据 |
| 中央画布 | 显示服务与中间件、连接语义、待部署差异和独立的运行状态；保持足够留白，提供缩放、适配与定位，不承载密集表单 |
| 右侧检查面板 | 按当前选择切换「配置 / 运行 / AI」；无选中项时显示项目摘要与下一步。切换选择保留可解释上下文，不把服务 A 的 AI 变更显示成服务 B 的结果 |
| 底部事件日志 | 默认折叠，异常显示计数与简短摘要，可展开并按服务、阶段、操作过滤。显示时间与关联部署，脱敏后呈现错误与重试入口 |

侧栏可折叠；空间不足时一次只展开一个侧栏，保留当前选中项。窄屏与页面放大时用列表和独立详情视图完成同样任务，不通过缩小文字维持三栏。完整拓扑编辑的窄屏布局需要后续原型验证。

## 画布与代码工作区切换

顶部提供「画布 / 代码」切换。代码模式复用五区布局：左侧改为按服务独立仓库分组的项目目录树，中央改为多标签文本编辑器，右侧继续提供配置 / 运行 / AI，底部保留事件和检查结果。画布模式的组件目录与 React Flow 职责保持原意；可从选中服务、AI 变更或检查位置进入对应代码，具体见[简单代码编辑器](code-editor.md)。

文件标签标明服务、相对路径、未保存 / 只读 / 冲突状态，支持打开、切换、关闭和显式保存。普通切换保留缓冲区；关闭有未保存内容的标签或项目时，可保存后继续、放弃修改或取消，保存失败则保留内容。顶部区分文件保存与画布草稿状态，文件保存不隐含 Git commit、远端同步或部署。

活动标签关联服务上下文，已有 AI 任务固定其发起时的服务与版本。AI 候选改动先比较和审阅，不能覆盖未保存缓冲或基准之后的人工修改；冲突处理、受控路径和文件边界在编辑器专题统一定义。标准中间件的运行数据不进入源码目录树。

## 右侧面板与服务级 Git

| 页签 | 主要信息 |
| --- | --- |
| 配置 | 名称、输入 / 输出契约、业务场景、依赖、非敏感配置及生效模型。业务服务显示技术栈、运行环境 / 框架版本与工程规则方案摘要，并包含自己的「代码仓库」区域：本地仓库状态、可选 GitHub 目标、初始化 / 同步状态、当前源码版本；标准中间件不显示业务源码与技术栈配置 |
| 运行 | 当前部署、实际 commit 与镜像 digest、实例状态、健康检查、就绪情况、观测时间、配置应用结果及相关日志。未部署时显示未部署，不用草稿内容填充为运行事实 |
| AI | 当前服务及画布 / 源码基准、实际加载的通用 / 技术栈 / 项目文档与固定版本、规范就绪状态、任务工具 / 外发许可与剩余预算、执行阶段、变更摘要、检查证据与审阅入口；新增依赖、规范 / 规则调整和跨服务改动显式列出 |

创建服务时默认选择「本地 Git」。选择 GitHub 后展示「先在本地创建，再同步」和「先在 GitHub 创建，再建立本地仓库」两条路径；具体认证交互另行设计。项目可以汇总多个仓库状态，每项仓库操作都明确指出所属服务及目标仓库。

拖入业务服务后，同时选择该服务的技术栈与受支持版本；模板、规则集和工具链由工程方案解析，详情可展开审阅，无需逐项手填工具配置。未选择、存在规则冲突或版本不受支持时显示未就绪原因，不直接进入开发或部署。具体流程见[服务技术栈与工程规则](service-engineering.md)。

AI 开发前展示[项目规范前置校验](ai-development-standards.md)结果：项目 `AGENTS.md` 是否引用工程规范、适用文档是否已读取、来源版本与范围是否明确。缺项时保留只读说明和补充方案入口，不继续代码生成；既有 `AGENTS.md` 的补充作为可审阅变更，不静默覆盖。

技术栈配置同时提供对应最佳实践文档的只读入口、包版本 / 来源及离线可读状态；服务 AGENTS 引用与本次 agents 实际加载结果分别展示，不把「文档存在」当作「任务已读」。不具备完整文档和验证入口的组合不得显示为已支持。

凭据区域只显示引用、用途、已配置 / 缺失等状态；本方案不设计在前端、日志或 AI 对话中展示明文密钥的入口。

标准中间件配置面板按[固定版本 schema](standard-middleware.md)生成或绑定字段，连接列表展示端口、数据库用途、兼容 / 未就绪原因和凭据引用状态；不展示密码值。运行页展示数据库 / 迁移 / 服务就绪的独立阶段和已核实的应用入口。首次本机配对、会话失效与重新授权依[运行设计](operations-and-recovery.md#首版本机初始化与认证建议)反馈，不借业务应用入口访问控制面。

## 草稿、部署与实际运行态

前端持有交互预览，平台服务持有已提交期望态。待审阅草稿、已接受的部署目标与实际观测需要分别标识；保存草稿不会立即调和运行环境，何时接受为部署目标由审阅或明确授权的策略决定。

| 状态或转换 | 用户应看到什么 |
| --- | --- |
| 草稿有未保存修改 | 草稿标记与保存状态；当前已部署版本与实际运行状态继续可见 |
| 草稿已保存、尚未部署 | 草稿版本与待部署差异，不能显示为「已上线」 |
| 仓库初始化 / 远端同步失败 | 所属服务、失败阶段、本地仓库是否可用与重试入口；不混同运行故障 |
| 文件未保存 / 保存失败 / AI 与人工修改冲突 | 所属服务、文件与工作区、未保存内容及基准差异、保存或比较入口；保留缓冲区，不改变运行版本，也不把文件已保存显示为已部署 |
| 构建或测试中 / 失败 | 对应服务、源码版本、阶段和结果；失败变更不进入项目空间 |
| 规范引用缺失 / 不可读 / 范围冲突待处理 | 目标项目与服务、引用或文档路径、已读取范围、阻塞原因与下一步；只读定位可继续，开发写入与交付暂停，运行版本保持真实回显 |
| 工程检查未运行 / 工具出错 / 待人工审阅 | 服务所属技术栈与规则版本、真实执行状态、规则定位和待办；这些状态与「运行健康」分别显示，不能用绿色健康标记代替检查结果 |
| 部署与调和中 | 目标版本、当前实际版本、进度与未收敛项；不能提前清除差异或显示成功 |
| 操作已受理 / 等待重试 / 需人工处理 | 操作 ID、目标代次、已完成与未知步骤、下次重试或处理入口；202 不表示上线成功，平台重启后可继续查询 |
| 进程运行、健康未通过或未知 | 分别显示「运行中」与「未就绪 / 检查失败 / 未知」；运行中不等同服务健康 |
| 实际态偏离部署目标 | 差异、观测时间、原因与可采取的动作；新草稿尚未部署的差异单独说明 |
| 状态连接中断或观测过期 | 「状态未知 / 观测已过期」与最后观测时间，不能沿用旧健康标记冒充实时状态 |
| 替换失败或回滚 | 显示失败与恢复阶段，核实实际版本后更新结果；单列数据库和消息状态的恢复边界 |
| 停止 / 移除 / 删除中或部分清理失败 | 列明动作、具体资源、保留源码 / 卷、已清理和残留项，不以项目卡片消失冒充清理完成 |

原子保存、版本 / 幂等和事件恢复遵循[契约设计](canvas-contracts.md)，调和与资源生命周期遵循[运行与恢复](operations-and-recovery.md)；机器 schema、观测阈值和具体交互仍待实现验证。前端不得因本地编辑或动画结束就宣告状态收敛。

## 变更审阅与部署入口

审阅视图按用户能判断的变化组织：画布组件与连接、各服务的源码差异、模型 / 迁移、配置及生效模型、依赖变更、工程方案变化、检查结果和拟部署版本组合。每个服务列明所属仓库、基准与目标 commit、镜像和证据，清楚区分 AI 建议、已接受修改与当前运行版本。工程规则结果展示已执行范围、待人工判断项和例外，不使用笼统的「全面符合最佳实践」结论。

审阅绑定具体画布与源码版本；期间版本变化时，提示重新比较与验证，不能把过期结果当作当前授权依据。构建 / 测试未通过、仓库未就绪或缺少必要配置时，部署入口说明阻塞原因。自动部署是否允许预先授权、授权粒度和默认策略仍待确认；页面始终保留变更摘要与可追溯证据。

部署结果回到工作台的运行面板与事件日志。回滚入口显示上一可用版本及影响，代码 / 镜像回退与数据恢复分别表述，详见[仓库设计](service-repositories.md)。

停止、从画布移除、删除项目、删除源码与删除业务数据分别入口或分别选择，执行前展示具体影响与保留项。备份 / 恢复入口展示范围、版本、校验及目标位置，恢复到新位置验证后再切换；界面不默认替用户选定远端备份、保留期或完整离线能力。

## 订单发券场景与验证顺序

目标场景可以按「订单服务发布订单事件 → RabbitMQ → 发券服务 → MySQL」排布。事件连接标明事件名和方向，数据库依赖标明读写用途；这些是声明关系，不能在缺少运行观测时画成实时流量。

用户选中发券服务后，可在配置页查看它自己的 Git 仓库，在 AI 页提出业务规则修改，在审阅视图检查源码、依赖与迁移，最后在运行页追溯已部署 commit、镜像和健康结果。订单服务保留自己的仓库与版本。该场景用于解释完整目标，不代表第一版已具备订单、RabbitMQ 或 AI 功能。

首个端到端验证切片采用数据库版 Todo List 示例项目（MySQL 与一个手写 Todo 服务），先验证画布编辑、服务端保存、Todo 数据持久化、真实 compose 生命周期、状态回显与错误恢复。Todo 仅用于演示和验证通用工作台流程，真实用户项目仍按业务需求编排。独立本地 Git 的最小登记和固定 commit 追溯从该切片提供；完整 Git UI、编辑器、AI / GitHub 后续接入，不为展示完整页面提前搭建功能外壳。

后续原型需验证五区布局的密度、长名称与版本信息、草稿 / 实际态辨识、服务切换上下文、目录与多标签编辑、未保存保护、AI / 人工冲突、键盘添加与连接、窄屏 / 缩放及深浅主题。无障碍与节点规则见[设计语言](design-language.md)，本次不声称已通过可用性或无障碍测试。
