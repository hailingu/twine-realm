# AI 交互开发与简单代码编辑器设计

> **状态：设计方案，未实现。** 已确认能力要求：AI 交互开发项目时，用户能够查看项目目录结构、编辑文本文件，并以多个标签页展示代码。下文的工作区、布局、保存与冲突处理是待验证提案；本轮不创建编辑器、文件 API、业务仓库或依赖配置。

## 目标与首版范围

代码编辑器让用户在同一项目上下文中查看 AI 产物、阅读目录、手工调整代码并参与变更审阅。首版围绕目录树、打开已有文本文件、多标签切换、基础输入 / 选择 / 复制粘贴 / 撤销重做和显式保存组织，不以完整 IDE 为交付条件。

语言服务器、智能补全、调试器、集成终端、插件生态以及文件新建 / 重命名 / 删除等扩展能力另行评估。语法高亮与编辑器组件选型也待验证，本设计不指定组件库或新增依赖。编辑文件不会自动执行代码、提交 Git、同步 GitHub 或部署。

## 项目目录与每服务独立 Git

目录树是服务端登记的项目与工作区的受控视图，延续[每服务独立 Git](service-repositories.md)，不是浏览整台机器的文件管理器。

| 层级 | 展示与编辑边界 |
| --- | --- |
| 项目 | 归组项目规范入口与各服务；标明服务仓库身份，不将项目目录解释为共同 Git 仓库 |
| 项目级规范入口 | 可只读定位项目 `AGENTS.md` 与已登记规范；项目级内容的修改沿用规范变更流程，不通过普通服务文件保存接口改写平台元数据 |
| 业务服务 | 每个服务展开自己的仓库目录，显示当前工作区、分支或基准版本；只在该服务获准编辑的本地工作区打开文本文件 |
| AI 候选工作区 | 与人工编辑工作区分开标识；候选文件和差异默认只读，接受修改时再按冲突规则应用 |
| MySQL 等标准中间件 | 仍从画布配置与运行面板管理，不提供业务源码目录；数据库文件、卷与运行容器路径不进入代码树 |

例如，数据库版 Todo List **示例项目**的目录树展示 Todo 服务的源码、测试、迁移文件及服务 `AGENTS.md`，MySQL 保留为画布基础设施。这个例子只用于演示和验证，不是固定项目模板；其他项目按各服务的真实技术栈与目录组织展示。

文件和标签以「项目 + 服务 / 仓库 + 工作区 + 相对路径」确定身份。同名的 `README.md` 或 `src/index.ts` 在不同服务中是不同文件，标签与路径提示须能区分；不把本机绝对路径用作跨环境身份，也不展示平台自身仓库为业务项目代码。

## 画布、目录、代码与 AI 布局

沿用[五区工作台](workbench.md)，顶部增加「画布 / 代码」工作区切换：画布模式保持组件目录与 React Flow；代码模式左侧展示项目 / 服务目录树，中央展示文件标签与文本内容，右侧保留配置 / 运行 / AI 面板，底部仍是折叠事件与检查记录。进入代码模式时优先展开 AI 页，之后保留用户选择。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 项目 / 服务    画布 · 代码    文件保存状态    当前运行版本 / 审阅入口 │
├───────────────┬────────────────────────────────┬────────────────────┤
│ 项目目录      │ Todo / README.md  ×            │ 当前服务 / AI 任务 │
│ ▾ Todo [Git]  │ Todo / src/…  · 未保存  ×     │ 规范就绪 / 基准    │
│   AGENTS.md   ├────────────────────────────────┤ 需求对话 / 阶段    │
│   src/        │ 文本编辑区                     │ 变更摘要 / 审阅    │
│   migrations/ │ 相对路径 · 可编辑 / 只读       │ 检查证据          │
├───────────────┴────────────────────────────────┴────────────────────┤
│ 事件 / 检查结果    所属服务 · 阶段 · 版本                            │
└─────────────────────────────────────────────────────────────────────┘
```

从画布选中业务服务可进入其代码目录；AI 变更摘要或检查定位可打开对应文件与位置，候选版本须明确标为只读。活动标签关联右侧服务上下文；已有 AI 任务始终绑定发起时的服务与工作区，不能因切换文件而改投另一个仓库。切回画布保留标签、滚动位置与未保存内容，不隐含保存或接受修改。

侧栏可折叠，窄屏用目录 / 文件 / AI 详情切换，保持当前文件与任务可辨认。外观沿用[设计语言](design-language.md)的暖白背景、细灰分隔、等宽代码字体与独立焦点标记；未保存、只读、冲突同时用文字或图标表达。目录展开、标签切换与关闭、保存和退出编辑区都须可用键盘操作；编辑区的缩进键不能造成焦点陷阱，具体快捷键与辅助技术表现待原型验证。

## 打开、保存与状态

打开文件时由服务端核对项目、仓库、工作区和路径，返回支持的文本内容与文件修订标识。编辑缓冲区只表示尚未保存的人工草稿；服务端工作区的已保存文件、Git commit、画布草稿、部署目标与当前运行版本分别标识。

| 操作或状态 | 目标行为 |
| --- | --- |
| 打开与重复打开 | 只读入允许的普通文本文件；同一文件身份复用已有标签。加载失败说明原因，不以空内容冒充原文件 |
| 编辑后未保存 | 标签显示未保存标记和所属服务；切换标签继续保留缓冲区，不能由后台刷新覆盖 |
| 保存当前文件 | 显式保存至该服务的本地工作区；以打开或上次成功保存的文件修订为前提，服务端在写入时再次校验，单文件原子写入成功后才清除未保存标记 |
| 保存失败或结果未知 | 权限、磁盘、连接等失败保留缓冲区并显示原因；连接中断不能报告成功，先核对实际文件内容 / 修订再决定重试，避免盲目覆盖 |
| 文件已保存 | 展示本地工作区已保存，Git 未提交状态另列；不把文件保存理解成画布保存、commit、推送或上线，也不自动运行格式化与构建 |
| 外部已修改、删除或移动 | 无未保存内容时可提示后刷新；有未保存内容或保存基准不匹配时进入冲突状态，保留缓冲区与可比较版本，不静默重建、覆盖或改绑文件 |
| 不支持编辑 | 二进制、超出受支持编码 / 大小边界或只读内容显示明确原因，不以截断内容写回文件；具体限额待实现时确定 |

首版以单文件显式保存为基线；若后续提供「全部保存」，逐文件报告成功、冲突与失败，不承诺跨文件或跨仓库原子保存。前端状态变化和请求发出都不能作为落盘成功证据。

文件修订是服务端生成的不透明前置条件，关联明确的仓库 / 工作区代次、相对路径、当前文件身份与内容摘要；不单凭 mtime 或 Git HEAD 判断工作区文件是否变化。推荐 HTTP 使用 ETag / If-Match 表达条件保存，实际格式在文件契约中固定。保存协调平台工作区写入，复核基准后采用同文件系统的临时文件原子替换；版本不匹配返回冲突与当前修订，不先覆盖再提示。平台锁不能锁住所有外部编辑器，外部改动与 Git 版本切换仍需按并发流程检测和对账。

保存请求带稳定操作 ID 与内容摘要；同意图的重复请求返回原结果，同键异内容拒绝。连接中断时查询原操作及当前文件修订，判断原写入是否完成；原写入后又有新编辑时，不把原内容重新写回。单文件原子替换只保证该次文件替换边界，不声称元数据库、Git 和文件系统共同原子提交。

平台条件保存的强保证覆盖参与工作区协调的编辑、候选应用与 Git 入口。**内容摘要检查后再原子替换，不构成对任意外部编辑器的文件系统比较并交换**：外部进程在复核后写入仍可能产生竞态。首版建议同一人工工作区只通过一个受控写入口操作；使用外部工具前暂停平台写入、重新读取并核对文件 / HEAD，独立外部检出通过显式比较导入。检测到外部变化时停止自动应用，保存可获得的基准 / 候选恢复信息；未能捕获的瞬时外部版本不能宣称一定可恢复。若将来承诺任意外部并发无丢改，需先有更强的工作区所有权或存储方案及相应证据，不能只增加一次哈希检查后扩大保证。

## 切换、关闭与未保存内容

- 切换标签、服务或画布 / 代码模式时保留各文件状态；活动服务和 AI 任务归属持续可见，不因暂时隐藏编辑器而丢弃修改。
- 关闭含未保存内容的标签、关闭项目或更换将移除当前工作区的仓库 / 版本时，列出受影响文件，提供「保存后继续 / 放弃修改 / 取消」。保存失败或发生冲突则停留并保留内容；放弃只丢弃明确选中文件的未保存缓冲，不删除已保存源码或其他服务工作。
- 刷新或离开页面使用浏览器允许的离开提示；不能承诺崩溃、强制关闭或断电后自动恢复未保存内容。未成功保存时不显示「已保存」；自动备份与恢复策略另行设计，不默认把源码或敏感内容持久化到浏览器缓存。

## AI 与人工修改的协调

AI 继续在服务隔离工作区开发，人工编辑器默认操作该服务的人工工作区。任务启动时明确所用的**已保存源码快照**、基准 commit 与实际未提交内容摘要；未保存缓冲区不自动进入 AI 输入。涉及的文件尚未保存时，先提示保存并重新固定快照，或在用户明确选择后基于已有保存版本继续，界面持续提示两者差异。当前打开文件也不等于授权把整个目录发送给 AI。

AI 产生的修改先作为绑定基准版本的候选差异展示。接受修改前，服务端核对人工工作区的文件修订、创建 / 删除状态，前端同时检查受影响文件的未保存缓冲区。人工保存、外部工具改动或新的 AI 结果使基准过期时，不能按最后写入者覆盖，也不能用强制刷新清除用户内容。

受影响文件存在未保存修改时，先保存、明确放弃或取消本次应用；随后仍要比较最新已保存文件。冲突时展示共同基准、当前人工版本与 AI 候选的差异，允许用户形成新的待保存文本再校验；首版只要求可比较、可人工处理，不承诺自动合并或完整合并工具。无关文件的缓冲区继续保留。多文件应用按受影响集合预检，失败或部分应用必须如实报告，不把局部成功标为整项接受完成。

多文件应用登记操作 ID、完整目标集合和逐文件前后摘要 / 修订、完成状态与恢复信息。执行中断后先核实每个文件：已达到候选版本的只结清，仍为基准的可按许可接续，出现第三种内容则停止并发冲突处理。若提供补偿，仅在文件仍是本次写入后值时恢复原内容，不能回滚掉后来人工修改；跨文件原子应用不作为首版承诺。

保存、应用 AI 候选与 Git checkout / merge / commit 共享工作区协调；外部 Git 操作使 HEAD、分支或工作区代次变化时，旧保存与候选结果不能自动转投新版本，具体见[Git 并发保护](service-repositories.md#ai-修改与构建边界)。推荐同一可写工作区只运行一个 AI 写任务，分析任务可并行；worktree 隔离不替代执行器安全限制。

人工与 AI 修改均遵循[项目规范](ai-development-standards.md)和[服务工程方案](service-engineering.md)。规范引用缺失时允许只读定位与按规范流程补充，不能借编辑器入口绕过 AI 任务前置校验；修改服务 `AGENTS.md` 或工程规范须显式审阅并使相关上下文重新校验。保存或接受源码变化后，旧检查结果保留其原版本归属，当前代码须重做受影响检查；构建部署仍绑定不可变 commit。

## 文件访问与内容安全

所有目录枚举、读取、保存与候选差异应用都由服务端校验授权的项目 / 服务 / 工作区及相对路径。拒绝绝对路径、路径跳转、编码绕过与越界链接；首版不跟随符号链接读写，打开和写入时复核实际文件对象，防止校验后的路径替换。来自浏览器、AI 或仓库内容的路径都不能扩展允许根目录。

`.git` 内部文件、平台自身目录、其他项目目录、运行容器 / 数据卷和登记的凭据路径不向编辑器或 AI 暴露。脱敏配置示例按策略作为普通文本处理；忽略文件或隐藏目录的展示过滤不代替访问控制。文件内容和名称按文本呈现，不执行仓库中的脚本、HTML 或指令，不因打开文件就授予网络、终端、安装、推送或部署权限；凭据与错误信息遵循现有隔离、脱敏规则。

## 后续验证与待定事项

以下为未来验收方向，本次没有实现或执行产品功能验证。

| 场景 | 应观察到的结果 |
| --- | --- |
| 打开 Todo 示例项目目录 | 可查看 Todo 服务源码、测试与迁移文件，多标签编辑；MySQL 数据和平台源码不进入树中 |
| 多服务打开同名文件 | 标签、保存目标和 AI 任务归属可辨认，各自保存到独立仓库 |
| 未保存时切换标签、服务或画布 | 缓冲区保留，切回后内容和状态一致；关闭时可保存、放弃或取消 |
| 保存失败、响应中断或外部修改 | 不丢缓冲，不虚报成功，核对实际版本后处理，拒绝过期覆盖 |
| AI 候选与人工修改同一文件 | 未保存内容和已保存改动都参与冲突检查，接受前可比较并人工解决，不覆盖无关文件 |
| 手工修改规范或检查配置 | 显式标记规范变更，AI 重新校验上下文，旧检查不能作为新版本通过依据 |
| 访问越界路径、符号链接或敏感目录 | 目录、读取与保存各入口均拒绝，错误不暴露敏感内容 |
| 大文件、二进制、窄屏与纯键盘操作 | 不截断写回，边界原因可见；可完成目录导航、标签切换、保存与退出编辑区 |

编辑器组件、文本编码与大小限制、文件修订 / 操作查询的机器 schema、写入协调工具、快捷键及原型可用性仍需细化。条件保存、结果未知先核实和逐文件恢复的原则已定义。沿用首个手写纵向切片，后续在服务级 Git 与 AI 交互阶段接入简单编辑器，不先建立完整 IDE。
