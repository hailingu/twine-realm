## 版本与事实所有权

以下是逻辑概念；字段拼写、枚举和数值上限在首次契约发布时固定。

| 记录 | 最少内容与所有者 |
| --- | --- |
| 画布文档 | schema 版本、项目 ID、服务端递增的画布 revision、组件、连线与用户明确设置的布局；服务端保存已确认版本 |
| 组件定义 | 定义 ID、不可变定义版本、组件类别、配置 schema、端口集合、配置生效模型与能力声明；目录仅发布适配器实际支持的组合 |
| 组件实例 | 稳定组件 ID、定义与版本、非敏感配置、配置 / 凭据引用、归属和布局；各组件类别使用精确配置结构 |
| 连线 | 稳定连线 ID、关系种类、两端的组件 ID 与语义端口 ID、接口 / 消息契约引用，以及该种关系适用的参数 |
| 部署目标 | 接受时的画布 revision、独立递增的目标代次、不可变部署清单；保存画布不会自动接受为部署目标 |
| 操作与运行观测 | 操作 ID / 版本、目标代次、资源身份、已观测版本、健康、错误与采集时间；独立于画布文档持久化 |
| 事件 | 项目内单调 sequence、事件 ID、类型、协议版本、关联画布 / 目标 / 操作版本、发生时间及受校验载荷 |

画布 revision、部署目标代次、操作版本和事件 sequence 各司其职。运行进度不增加画布编辑历史；事件到达也不证明运行已经收敛。凭据值、DOM 测量、React Flow 内部状态、选区和视口不进入画布文档。

同一组件 ID 不复用于删除后新建的另一实体；底层容器和卷使用独立资源身份。未知 schema / 定义版本明确拒绝并保留原始输入，不静默丢弃字段、节点或连线。首次尚未选择技术栈等可编辑状态允许保存为未就绪草稿，部署前再校验必需配置。

## 具名端口与关系校验

端口用稳定语义 ID 定位，定义方向、协议或值类型、连接基数、必需性和适用契约版本；名称本地化、节点移动及 Handle 的屏幕位置不改变身份。前端 Handle ID 映射到语义端口，服务端按相同定义版本复核。

连线至少区分数据库 / 中间件依赖、HTTP 调用和消息发布 / 订阅等关系。各类关系定义自己的端点角色和方向，标签说明调用、读写或事件用途；不能只凭线的颜色、箭头或节点类别猜测配置。连接数据库时，平台根据引用解析并注入连接信息，画布只保存非敏感声明与凭据引用。

适配 Infinity Canvas 时须作两项区别：

- 媒体生成的依赖图默认无环；业务服务的 HTTP 相互调用或消息回路可能合法。twine-realm 按关系类型验证循环，严格启动依赖的环须拒绝或要求显式就绪策略，不能一律拒绝所有业务循环。
- 业务事件的发送方向不一定等于部署启动顺序。启动依赖由编排规则推导并独立校验；有序性只在确有顺序语义的关系中声明，不把媒体多输入的 `order` 强加到所有连线。

创建、重连和删除在最终候选图上校验：定义版本、端口存在、方向与角色、协议 / schema 兼容、基数、重复关系、引用完整性及适用循环规则。前端预检用于即时反馈，服务端为最终裁决；不采用无依据的「所有 JSON 互相兼容」。兼容不了的连接需显式转换方案，不能暗中新增服务。

单输入替换与重连在一次编辑事务内完成，失败保留原边；删除节点同事务移除关联边。移除声明后的容器与数据处置另走[资源生命周期](operations-and-recovery.md)，不因领域级联删边就直接删除卷或源码。

## 标准中间件的预定义 Schema

标准中间件由目录提供预定义、版本化的 schema，至少覆盖组件非敏感配置、具名端口、连接绑定与适用兼容规则。前端、服务端、agents 和运行适配器解析同一固定定义包；通过 JSON 结构校验之后仍须验证整个候选图的关系和归属，不由任一消费端自行放宽。

服务实例引用定义 ID / 版本与 schema 身份；schema 包和适配器支持矩阵一起发布，首批以 MySQL 为验证对象。业务数据库表结构属于服务仓库迁移，不由中间件配置 schema 隐式代管；自定义服务仍可定义自己的多个接口、端口和版本。具体职责、发布规则、MySQL 注入 / 账号 / 迁移 / 运行方案见[标准中间件 Schema 与服务运行契约](standard-middleware.md)。

## 原子编辑、幂等与补偿

画布、表单、连接列表与 agents 共用领域编辑入口。事务带项目、mutation ID、基准 revision 和具有判别类型的操作集合；不开放任意数据库字段或任意 JSON 路径补丁。运行、取消、Git push 和卷删除分别授权、分别记录。

1. 一期以单可信 OS 用户、本机请求和项目边界为前提，严格解码并限制请求大小和操作数量；不开发账号、会话或 RBAC。未来身份接入时再从可信身份层取得主体与权限。
2. 一期按全局请求键与包含项目 / 类型 / 规范载荷的摘要查原结果；同键不同内容冲突。未来身份接入后增加主体与权限边界，不能把幂等键当授权。
3. 对新请求检查基准 revision，按顺序生成候选图，再验证最终完整图；整批成功或整批失败。
4. 在同一元数据库事务中更新文档与 revision、操作历史、幂等结果及持久事件。接受部署目标时，同事务保存目标与待处理操作；不在事务中等待 Git、Docker 或 SSE 推送。
5. 成功返回 mutation ID、新 revision 与服务端规范化操作；客户端只据确认结果推进已保存状态。超时 / 5xx 造成结果未知时先查询或原键原内容重试，不立即换键重发。

推荐首版每个项目编辑会话只保留一个在途提交，后续意图排队；版本冲突保留草稿，读取最新快照后供用户比较，不静默覆盖或自动重放冲突意图。项目切换或重开时变更会话代次，旧请求和旧事件不能写入新会话。

撤销已确认编辑是基于当前版本的补偿事务，比较相关字段的当前值与原后值；有后续修改则冲突。不能回写整份旧快照，也不能把普通画布撤销解释成撤销已发生的部署、远端写入或数据删除。跨系统执行与恢复见[运行与恢复](operations-and-recovery.md)。

所有对象固定字段、枚举、空值、大小与数值界限；引用采用稳定身份与版本，不能靠当前名称解析。凭据字段只允许用途与引用版本，真实秘密不在契约样例中。

首版部署的顺序屏障如下；不要求 Git、Docker、文件和数据库组成一个事务：

1. 保存草稿只提交画布编辑，可登记源码准备 / 构建操作，不改变当前部署目标，也不因草稿更新自动替代在执行部署。
2. 构建与检查针对固定 commit / 工程快照形成候选记录；未完成、失败或证据过期的候选不可接受为部署目标。构建不依赖先创建一份缺少镜像身份的「不可变部署清单」。
3. 审阅与接受部署绑定完整候选组合；接受时再次比较画布 revision、预期当前目标、源码 / 镜像、规范 / 配置及许可。任一相关内容变化则要求重新比较 / 验证，不沿用旧审阅；同目标重试不隐含接受新源码。
4. 同一平台数据库事务保存新的不可变目标清单、操作、幂等结果和事件。目标代次只在接受部署 / 停止 / 生命周期目标时改变，保存草稿或收到运行事件不改变它。
5. 执行后将观测与实际产物关联到原操作；成功必须满足已定义的整体就绪条件。失败不会把草稿回写成运行事实，也不自动把旧部署重新声明为当前目标；恢复或回退仍要固定清单并核对权限和数据兼容。

元数据库至少验证项目 revision / 目标代次的条件更新、主体 / 项目 / 操作类型 / 幂等键唯一性、请求摘要一致、步骤 ID 与资源身份的稳定关联及事件的项目内序号唯一性。严格连续的业务序号须与事件一起事务提交；不能用可能跳号的分配方式，再要求客户端把正常空洞当丢消息。资源动作在外部发生前持久登记操作和确定性身份，外部返回值未知不等于尚未创建。

操作允许的转换、取消 / 替代与恢复边界见[持久操作状态转换](operations-and-recovery.md#持久操作状态转换)；参数初值见[建议默认参数](operations-and-recovery.md#建议默认参数)。未知协议版本、超限或无法解析的结果返回明确错误，不能截断后按成功载荷处理。

## API 与事件的版本化契约

在首个消费端接入前固定版本化 OpenAPI、请求 / 响应样例和独立事件 schema，明确枚举、空值、限制、分页、幂等、受理与完成语义。类型不直接从数据库实体或 React Flow 对象导出，Go 和 TypeScript 均对外部输入做运行时校验。

契约只保留一个权威来源。首版推荐采用上一节的 schema 先行与生成 / 校验流程；若实现任务选择从实现生成契约，须显式记录取舍并保留同样的快照 diff 与真实消费验证，不能长期手工维护两份互不校验的真相。具体 Go 工具在切片中选定。变更须评审差异，并验证真实提供端与消费端行为。破坏性字段、定义或关系语义变更发布新版本，现有引用不得被原地改义；升级作为显式变更处理。

| 结果 | 语义与恢复 |
| --- | --- |
| 编辑成功 | 返回已提交 revision 和回执，表示画布保存完成 |
| 长操作已受理 | 返回 202、操作 ID 与查询位置；仅表示持久受理，不表示部署成功 |
| 请求或领域非法 | 区分格式错误与领域拒绝，指出安全的字段 / 规则原因，原图不变 |
| 身份失效 / 越权 | 401 / 403，停止受限动作，不无限自动重试 |
| 版本或幂等冲突 | 409，区分版本变化、同键异内容与同键仍在处理中；草稿和原请求保留 |
| 限流或依赖失败 | 429 / 5xx，遵循 Retry-After；结果未知先核实，再决定重试 |

错误统一包含稳定 code、安全 message、trace ID 和适用的字段明细 / 当前 revision；不返回凭据、内部绝对路径或原始 Docker / 提供商报文。具体错误码和路径在机器契约中发布，不照搬 Infinity Canvas 的 `/api/v3` 或租户路由。

## SSE 断线与快照恢复

SSE 是持久状态的通知与投影通道，执行器从数据库中的待处理操作恢复，不依赖浏览器连接或 SSE 消息触发业务。

- 初始化 / 恢复返回一致性信封：已确认画布、部署目标、操作及运行观测摘要、事件游标；各部分在同一平台数据库一致性读边界生成。运行观测保留实际采集时间、来源和新鲜度，不能将其描述成外部系统的跨系统快照。
- 客户端采纳信封后，从游标之后订阅；事件与状态提交同库持久化，项目内序号严格有序。序号在线格式使用规范十进制字符串，避免 Go 整数在 JavaScript 中丢失精度。
- 使用 Last-Event-ID 恢复；允许重复投递，客户端按 sequence 去重。跳号、过期游标、不认识的协议或非法载荷触发完整信封恢复，不能只刷新画布就跳过运行状态。
- 心跳不递增业务序号，追平控制帧不冒充业务事件；只有游标连续追平后才显示状态流已恢复。断流期间可做有界、退避且遵循 Retry-After 的状态查询，界面显示最后采集时间与过期状态。
- 一期订阅与重放校验本机请求与项目边界，不新增账号会话；未来身份接入后再校验当前身份与权限，不把长期 token 放入 URL。切换项目、页面销毁或未来身份失效释放流、轮询与请求，迟到结果需通过页面会话代次校验。

重放窗口、心跳与观测过期阈值采用[建议初值](operations-and-recovery.md#建议默认参数)做首个真实切片验证，再固定为公开配置；连接 / 帧 / 快照大小随机器契约明确，不照搬参考项目数值。事件回执与 HTTP 回执必须进入同一确认协调器，避免重复应用；推荐首版编辑确认以 HTTP 回执 / 原键查询为唯一入口，事件仅触发版本核对与恢复。

| 未知组件定义、非法端口、超基数或不兼容协议 | 明确拒绝，已有图和确认 revision 不变 |
| 重连失败、批量内含非法编辑 | 整批拒绝，原节点 / 连线保留，无部分保存 |
| 同键同内容、同键异内容、同版本并发编辑 | 分别重放既有结果、报告冲突、仅允许一次新版本提交 |
| 保存成功但响应丢失，或事件先于响应 | 原请求结清一次，不重复创建组件、不回退版本 |
| 合法消息循环与非法启动依赖环 | 按关系规则分别处理，不直接套用全图 DAG 限制 |
| SSE 重复、断连、过期和平台重启 | 重放或完整恢复画布与运行摘要，草稿保留，状态新鲜度真实 |
| 旧部署 / 旧会话响应迟到 | 不覆盖新目标和当前会话，保留其原操作归属 |
| 读取机器契约与调用真实接口 | 实现、快照及消费端行为一致，破坏性变化明确版本化 |
