# 项目一致状态、SSE 与断线恢复切片

对应 [Issue #18](https://github.com/hailingu/twine-realm/issues/18)。v5 读取契约与 v1–v4 并存，提供统一元数据信封、有序通知、窗口恢复及草稿保护。项目聚合停止由 [Issue #20 生命周期切片](project-lifecycle-slice.md)独立承接；不增加账号、登录、配对、RBAC、AI、产品 GitHub 同步或跨系统事务。

## 事实与执行边界

- `projectstate` 只读平台元数据，不拥有编辑、部署或后台执行器。`cmd/platform` 默认装配它；未装配的测试/嵌入实例返回 `STATE_DISABLED`，不偷偷拼接旧接口。
- 完整信封在同一 MySQL RR 事务读取项目、完整图、MySQL、各服务构建/部署摘要和项目游标。保留每个观测的实际采集时间、来源、诊断和独立新鲜度；平台数据库一致不代表 Docker、Git 与业务库同一时刻原子读取。
- 全项目 `cursor`、画布 `revision`、领域 `generation`、操作 `version` / `execution` 和 MySQL/部署自己的历史 `sequence` 各自独立，在线均使用规范十进制字符串。不能通过进度通知增加画布编辑历史。
- 通知只使消费端核实完整状态。HTTP 回执及原键查询仍是唯一编辑确认入口；事件先于响应也不能解除未知请求、换键重发或重复应用编辑。
- 读取连接取消、关闭页面与控制面退出只回收相应读取拥有者，不发送业务停止或取消目标。后台任务仍按已接受持久目标恢复。

## 公开契约与固定参数

权威来源是 [v5 schema](../../server/contract/v5/state.schema.json) 和 [OpenAPI](../../server/contract/v5/openapi.json)。Go 编译同一离线材料；前端类型与独立 Ajv 校验器经 `web` 的 `npm run contract` 生成，`contract:check` 防止漂移。

| 入口 | 语义 |
| --- | --- |
| `GET /api/v5/projects/{id}/state` | 完整项目、图、运行/构建/部署投影、cursor / replayFloor、capturedAt 与固定 policy；超限整体失败 |
| `GET /api/v5/projects/{id}/state/events` | 先核实项目和游标，再发送有界 UTF-8 SSE；初次使用 `after`，重连使用 `Last-Event-ID`；两者同时提供须一致 |

| 参数 | v5 当前实现 |
| --- | --- |
| 实际观测 / 过期 | 沿用约 5 秒采集 / 20 秒未成功采集过期，客户端断流时钟继续推进 |
| 心跳 / 无数据检查 | 15 秒注释心跳 / 45 秒客户端无数据取消自己的读取 |
| 重放窗口 | 每项目 24 小时且至多 100000 条，任一先到即失效；每页 200 条 |
| 完整帧 / 信封 | 4096 字节 / 64 MiB；不截成部分成功 |
| 活动流 | 每进程 16 条，每项目 4 条；超出 429，`Retry-After: 2` |
| 重连 | 2–30 秒有界退避，遵循更长的合法 Retry-After；超过一小时的外部重试期限要求手动重连，不静默缩短 |
| 读取与写入期限 | 快照 10 秒，单页 5 秒，每次流写入 5 秒；写完清零短期限，再等待下一心跳 |

普通 API 的 15 秒写期限继续保留；流通过 ResponseController 管理自己的短写入期限。平台 BaseContext 把正常退出传给在途请求，不等长连接拖到强制关闭。连接计数持锁期间没有 I/O，流拥有者退出时释放配额，不创建独立无界发送队列。

`state` 帧含十进制 `id` 和 `StateEvent`：项目 / 事件身份、sequence、scope、revision、适用的目标 / 操作 / 执行版本以及发生时间。`caught_up` 控制帧无业务 id，cursor 必须等于实际重放末尾。`resync` 同样无业务 id，要求完整信封后关闭；心跳不增加序号。秘密、SQL、原始工具输出和凭据值不进入通知。

| 失败 | 结果与恢复 |
| --- | --- |
| 非规范、溢出、重复或相互冲突游标 | 400；不猜测用户指的是哪个值 |
| 未知项目 | 404 |
| `STATE_CURSOR_EXPIRED` / `STATE_CURSOR_AHEAD` / `STATE_EVENT_GAP` | 写头前 409；写头后发送 resync 控制并关闭；重新读取完整信封 |
| 不认识的协议、错误身份、超大帧或非法 UTF-8 | 客户端保留最后事实，退避后完整恢复，不应用部分消息 |
| 普通网络失败 / 正常 EOF | 保留实际重放游标；重连前可核实较新信封，但不能据此跳过未重放事件 |
| 存储或写入未知 | 安全断流；保留最后事实和采集时间，不冒称资源已停止 |
| `STATE_SNAPSHOT_LIMIT` | 413；完整读取失败且保留草稿，不隐去部分服务 |

## 同库通知与保留窗口

`state-migrations` 及 `state_schema_migrations` 独立版本化，建立 `project_state_heads` / `project_state_events`。画布原子回执、MySQL/构建/部署受理、检查点、结算与实际观测刷新在原事务追加通知；原键重放不追加。项目 head 在既有聚合锁之后领取，与事件一起提交，回滚不留序号空洞，不使用 AUTO_INCREMENT 冒充连续序列。

正常观测即使状态未变也会刷新采集时间，因此项目通知仍覆盖它；领域审计可保留原有去重策略。旧目标、旧执行或迟到观测不获得新结果写入许可。外部动作和 SSE 发送均发生在事务之外。

新写入只裁剪项目通知的连续前缀并推进 replayFloor。长期没有写入时，读取仍按时间判定有效窗口；不因物理行尚在就重放过期数据。现有项目升级先从完整信封和 cursor 0 开始，不伪造历史通知；下一次真实变更从连续序号 1 开始。

`runtime_events`、`build_events` 和 `deployment_events` 保持各自永久历史；特别是 #16 的材料完成证明仍依赖不可变 `deployment_events`。短期 outbox 清理不能删除该证明。真实部署回归先裁剪项目窗口，再验证同一材料证明、原 MySQL/服务恢复和数据保留。

## 候选环境核实

v5 的构建投影来自持久元数据；`StateBuildSnapshot` 的 schema 将 `candidateCurrent` 限定为 `false`，不声称当前工作区、Docker 环境和镜像仍可用。所选服务保留 v3 的独立只读候选核实，只有项目/服务、当前源码、代次、候选和操作版本都匹配当前信封，才附着其可用性；不能用独立读取覆盖信封元数据。部署 preview / accept 的实际服务端预检完整保留。RR 事务内不执行 Git、Docker 或网络检查。

## 前端草稿与恢复

工作区唯一读取会话维护完整信封、实际流游标和追平状态。HTTP 信封可以领先重放游标；只有连续重放且视图已经追平，才显示「状态流已恢复」。重复通知去重，缺口/未知协议完整恢复；旧项目及旧流回调、被取消读取和较旧信封不覆盖新会话。

MySQL 和业务服务节点区分运行、健康、就绪、漂移、未知和过期；客户端时钟独立于网络。确认过的旧绿色不会在断流时永久保持。构建、部署面板继续展示原操作及版本，不以流连接成功代表业务成功。

没有草稿、在途/未知请求或打开表单时，可自动载入较新的图。有位置、服务接口、MySQL 配置或连线候选时，保留候选和原 baseRevision，显示远端声明供比较；用户显式载入后仍保留表单和实际改动位置，未改动节点采用远端位置。未知请求必须先按原键核实，通知不能替它确认。HTTP 回执结清自己对应的提示，不能清掉更高版本的远端变更。

## 验证与已知边界

根 `npm run test:platform` 覆盖 Go build/vet/race、共享契约、Vitest、真实 MySQL/Git/Compose 和 Chromium；`npm run precommit` 继续加入脚本、审计、真实 Sonar 和索引一致性门禁。新增目录沿用实际 Go / TS 源码发现和覆盖率，不排除新生产代码或降低阈值。

- 真实 SQL：并发 RR、通知失败整体回滚、原键重放、升级旧 schema、观测刷新、200 条分页、100001 条实际持久窗口的数量边界与无新写时的时间窗口。
- 真实 HTTP：Last-Event-ID 重放、429/释放配额、两次 15 秒心跳越过普通写期限、头后过期 resync、取消和控制面正常退出。
- 客户端受控时序：重复/缺口/过期、快照领先、旧流、Retry-After、空体/超限/UTF-8/半帧、命令与读取取消分离、草稿及未知回执。
- Chromium：真实断网、平台重启、真实超前游标 409 后完整恢复、位置/连线候选及原仓库保持；过期窗口本身由真实 SQL/HTTP 回归验证，不把浏览器的超前游标注入冒称时间窗口裁剪。

一期仍限本机、一个业务部署与原运行资源；不含多控制面分布式订阅、无限历史、任意 JSON patch、版本替换、项目聚合停止或物理数据清理。静态实现、单项测试、完整门禁、PR CI、合并和实际运行是不同证据；实时交付结论读取原 Issue / PR / Project。
