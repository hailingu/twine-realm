# 单服务 MySQL 部署切片（Issue #16）

**状态：本切片已接入实现与自动验收；本次门禁、提交、PR、CI 和合并必须分别核实。** 依赖 #8 / #10 / #12 / #14 已合入 develop。只处理已检查的本地 Go + 标准库 net/http 候选、一个服务和同项目 MySQL；Todo 是独立测试仓库，不是产品组件。一期不接账号、登录、配对或 RBAC，数据库用途账号不属于平台身份系统。

## 显式启用

先按[运行切片](mysql-runtime-slice.md)和[构建切片](service-build-slice.md)核实原私有根及安装。额外设置 `TWINE_DEPLOY_ADAPTER=go-mysql-compose-v1` 后启动平台，不新增秘密根；缺任一原适配器或使用未知组合时拒绝启动。默认能力为 `enabled=false / adapter=disabled / code=DEPLOY_DISABLED`，历史仍可查询。

业务应用只能使用工程包现有 `serve / migrate / migration-status` 组合和固定探针，平台不选择其他框架、不改写已发布工程包 1.0.0 的字节。私有业务材料位于原运行根 `projects/<resourceId>/services/<serviceId>/`，0700 目录、0600 文件；原文件丢失、版本或权限不符时明确阻塞，不能换根或生成新密码接管旧库。

## 接受边界

1. MySQL 先通过已有运行入口显式启动并认证就绪；服务仓库已有固定 commit、已发布工程包 `go-net-http-mysql/1.0.0` 和当前可用构建候选。
2. 预览固定画布 revision、服务契约版本、完整绑定 / 凭据引用、候选 / 工程 / 工具证据、MySQL 实例 / UUID / 卷 / 网络和运行策略。预览不执行 DDL 或创建容器。
3. 用户确认预览摘要后，同库复核 revision、构建和数据库目标，再保存不可变目标、原键回执、步骤与事件；事务提交后后台执行，不保持跨系统事务。
4. 运行配置按工程包注入 `HTTP_ADDRESS=0.0.0.0:8080`、服务名与绑定的数据库位置 / 用途账号 / 密码文件。服务自有 schema 独立校验；首版业务配置为空，要求它通过自己的 schema；未知自定义字段或映射明确阻塞，不忽略输入、不原地改写服务契约。
5. 应用入口为明确登记的 `127.0.0.1:<hostPort>`，建议初值 8081，范围 1024–65535。端口冲突失败，不抢占或自动换地址；业务 HTML 不代理到控制台同源。

## 机器字段与所有者

新增 v4 部署契约，与 v1 / v2 / v3 并存，字段由离线 schema 生成 TS 类型与校验器。

| 记录 | 内容与不变量 |
| --- | --- |
| 预览请求 | baseRevision、baseGeneration、candidateId、bindingId、hostPort、configuration；不含 SQL、命令或秘密值 |
| 确认请求 | 原预览参数、planDigest、mutationId 和可选 retryOf；原键先返回原回执，异意图拒绝 |
| 不可变目标 | 随机目标 ID、项目 / 服务、目标代次、固定预览；预览绑定完整候选、服务契约引用、数据库绑定 / 实例 / UUID、安装 / 环境及策略 |
| 物理资源 | 稳定服务 ID 与运行安装共同派生容器和材料身份；恢复沿用原身份，不用新容器 / 空库掩盖未知结果 |
| 操作与步骤 | 独立 operationId / version / execution lease，操作可为受理、执行、成功、失败、needs_attention；步骤未知结果使用 unknown，不能混用操作终态；副作用前后持久检查点，旧执行不写新目标 |
| 回显 | 实际容器 / 镜像、运行、存活、就绪、入口、数据库 / 迁移身份和 observedAt；保留最后事实及采集失败 / 过期；同目标按实际采集和尝试时间拒绝旧事实 / 旧失败，202 和 running 都不单独等于成功 |

入口为 `/api/v4/deployment/capabilities`、项目 / 服务的 `deployment/preview`、`deployments`、`deployment` 和原 `deployments/<operationId>`，回执通过 `/api/v4/deployment-mutations/<mutationId>` 核实。新代次先将旧事实标记为 `DEPLOY_PENDING`，执行失败保留旧内容和具体采集码，不能刷新旧 ready 为当前新鲜事实。`runtimeDigest` 固定物理内容，排除画布 / 受理并发版本及原 MySQL 运行目标代次；真正端口、候选、绑定、数据 UUID 或策略变化仍改变它。

`servicedeploy` 拥有模型、确认与持久工作器，`servicecompose` 拥有受信 Compose 适配；平台 store 复用现有同库读写屏障，新增独立迁移历史。MySQL 管理秘密留在 `mysqlruntime` 的窄项目会话内；构建模块只验证不可变候选，不接触业务凭据。

## 私网、秘密与数据库权限

- 与 MySQL 共用已有安装根、项目文件锁和私网，绝不并行改变同项目资源。服务材料保存在运行私有根的受限子目录，不在原服务仓库。
- 保留原 MySQL 固定 Compose 材料，通过已接受目标生成并核实服务补充文件；同一真实 Compose project 只执行指定服务，MySQL 和服务入口均验证补充材料。不屏蔽 orphan 告警，不接管外来容器。
- 固定候选镜像，运行用户为明确冻结的宿主非 root UID/GID，使 0600 秘密能按实际 Compose bind 语义读取；不假装 file secrets 支持 uid/gid 重映射，不改成 0444。
- 应用与迁移秘密分开、只读挂载到对应容器。MySQL 与迁移只连接原 internal 私网，不发布数据库端口；应用同时连接本服务拥有的入口 bridge，HTTP 只发布到 `127.0.0.1`。两个网络仍属于同一 Compose 项目。入口网络允许 Docker 常规出站，不宣称业务进程完全断网；应用不挂载管理 / 迁移密码、源码、宿主 socket 或其他项目。
- 真实 Docker 29 验收已证明，仅连接 internal 网络时虽然 HostConfig 保存了端口声明，NetworkSettings 中没有实际发布，不能将此当作可访问业务入口。因此入口网络独立创建、按完整安装 / 项目 / 服务 / 运行摘要 / 角色标签和配置核实，不能接管同名网络或忽略端口事实；数据库网络的 internal 语义保持原样。
- MySQL 管理通过有界交互会话执行平台生成的 SQL，秘密不放 argv / env。会话先取得数据库锁再发写入，未知 SQL 结果须先核实；输入、输出、时限与子进程所有权有硬边界，原始敏感输出不进入日志 / API。
- 管理 SQL 显式接收当前阶段的 context；阶段取消会中断原客户端并使该会话停止后续写入，回收仍由串行拥有者完成。客户端退出不代表数据库在途 DDL 已回滚，恢复仍须查询原任务、锁、dirty 和摘要。工作器执行或许可监测异常同样保留安全的待核实结果，不传播 panic 原文或留下无拥有者的监测协程。
- 每绑定固定数据库与账号，服务名改动不重建。检查已有对象和管理登记的归属，不重置密码、不认领同名外来库 / 用户。按实际 MySQL 授权语义处理数据库名下划线与账号网络范围。
- 迁移身份只具备本业务库需要的 DDL / DML；应用按用途获得业务表 DML 或 SELECT，迁移历史仅可读，不获全局 / 跨库 / 授权 / DDL 能力。被动核实同时检测账号的唯一原 Host、应用可连接 / 迁移账号已锁定，以及完整权限集合；发现额外或缺失授权、角色状态或秘密漂移就报告冲突，不用旧连接健康掩盖它。

## 迁移与恢复矩阵

| 前态 / 动作顺序 | 可观察结果 | 不变量与验证 |
| --- | --- | --- |
| 缺当前候选、绑定不合法、MySQL 未就绪 / 请求预览或确认 | 明确拒绝，没有 DDL / Docker 写入 | 先只读验证，再同库复核，客户端预检不代替后端 |
| 预览后 revision / 绑定 / 候选 / DB 目标改变 / 确认 | 预览过期，保留输入并重新审阅 | planDigest 与原键不被静默替换 |
| 同库受理 / 秘密、建库、迁移、应用逐步执行 | 每步先登记再动作，结果与实际身份一致才推进 | 管理凭据只在数据库适配器，事务内不做外部 I/O |
| 已应用迁移 / 查询历史 | 验证版本、dirty 与 up 文件摘要，已完成不重跑 | 不清 dirty、不强改版本、不覆盖历史摘要 |
| 迁移运行 / 平台退出、响应丢失或租约到期 | 先核实原任务容器、数据库锁与历史，无法确认则 needs_attention | 旧进程 / SQL 未结束不启动第二迁移，不盲重试 DDL |
| 阶段取消 / 管理 SQL 阻塞，或执行器异常 | 原通道停止后续写入、回收监测并保留未知结果 | 不以客户端退出当作 SQL 回滚，不把异常结算为成功 |
| dirty、迁移失败、DB 断连、探针失败或端口冲突 | 安全的具体阻塞与部分资源可查，不报告整体成功 | 数据 / 原容器 / 秘密保留，不自动换库、端口或凭据 |
| 全步骤完成 / 近期探针与版本核实 | 发布独立回环入口与真实就绪事实 | 只有当目标 / 执行代次仍当前才结算成功 |
| 成功后外部停改资源 / 采集 | 漂移或未知，保留时间与原目标 | 不自动接管 / 重建；同一候选显式恢复重新核实 |
| 首次部署在材料生成前失败 / 停止并恢复 MySQL | 没有业务材料与资源时，原 MySQL 可独立恢复 | 以持久材料完成记录和实际缺席证明区分从未生成，不能只看新操作的 pending |
| 已完成材料后文件丢失 / 新恢复操作 | 明确阻塞并保留原数据，不忽略原扩展 | 同一物理计划的历史完成证明跨操作、跨执行代次保留；文件和资源未知不按缺席处理 |

当前固定策略：总 360 秒、迁移 / 启动就绪各最多 120 秒、租约 420 秒、单条 Docker 命令 45 秒、观测 5 秒 / 20 秒过期。应用与迁移使用非 root、只读根、cap 全移除、no-new-privileges、512 MiB 内存与相同 swap 上限、64 MiB tmpfs、1 CPU / 128 PID；敏感运行原输出不作为普通日志采集，Docker 日志驱动为 none，安全诊断来自退出状态、实际迁移历史与探针。固定默认 PATH 也显式声明并核实，不能据此允许额外环境。

## 验收与后续

独立示例使用客户端 UUID：`POST /api/todos {id,title}`、`GET /api/todos`、`PUT /api/todos/{id} {title,completed}`、`DELETE /api/todos/{id}`。同 ID 重放不新增记录，未知创建按原 ID 查询。真实业务入口验证 CRUD、服务 / 控制面重启后数据仍在；源仓库保持只读。

首版只接受原物理计划的明确恢复，不能借新键更换候选、端口、绑定或配置；端口占用后释放该占用，再使用原计划恢复。控制面正常退出释放原租约，重启核实原任务、SQL 锁与历史；异常退出保留租约期限和原执行代次。首版不承诺数据回滚或零停机升级；缺失原秘密 / 归属证明时等待恢复原材料。SSE 由 [Issue #18](project-state-slice.md)承接，项目聚合停止仍待后续原任务，源码 / 业务卷删除和真实业务数据开放前的备份恢复不在本项范围。

MySQL 扩展读取同一物理计划的历史材料完成证明，不能仅看新操作的 pending 或重领后被覆盖的步骤。该证明来自持久 `deployment_events` 的不可变操作检查点，不属于 v5 SSE 通知的短期重放窗口；若以后裁剪此审计记录，必须先保留等价的完成证明。只有未完成过材料且应用、迁移与入口网络均经确定名称和归属名单证明缺席，才允许原 MySQL 不加载未完成扩展；既有文件仍须逐字节校验，权限错误、链接、未知资源和已完成后丢失均阻塞，不补造业务材料或秘密。

最终必须通过 Go/TS/schema、真实 SQL / Docker / Chromium 的成功、失败、原键和恢复场景，完整零告警提交 hook、根/web审计、Sonar 和准确 head 的 Linux CI；实际实现与边界在交付时更新本页和文档索引。

授权语义参考 [MySQL 9.7 GRANT](https://dev.mysql.com/doc/refman/9.7/en/grant.html) 与[账号网络范围](https://dev.mysql.com/doc/refman/9.7/en/account-names.html)：表级授权的数据库名按字面处理，数据库级授权须根据 partial_revokes 正确处理下划线；账号 Host 使用本私网的 IPv4 网段 / 掩码，不使用广泛且已弃用的通配模式。具体生成结果仍须由真实权限拒绝测试证明。
