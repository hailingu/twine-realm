# TypeScript 与 React 开发规范

本规范适用于前端画布（目标目录 `web/`）与 TS 工具脚本，与[软件工程规范](software-engineering-standard.md)共同使用。`web/` 已建立，检查见[质量门禁](quality-gates.md)。

## 工具链基线

- 构建工具 Vite，测试 Vitest，包管理器 npm（单一包管理器，`package-lock.json` 拥有依赖真相）；Node 版本基线见[运行时与工具链](runtime-toolchain.md)。
- 依赖最简：UI 层 React + React Flow（`@xyflow/react`）为既定选择，其余组件库与状态库按真实消费者引入，不预设。
- 验证命令（`web/` 已接入）：`typecheck && lint && test && build` 四件套；具体脚本在工程初始化任务中定义并登记到根指南范围路由。

## 类型系统

- `tsconfig` 以 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 为目标，编译范围覆盖全部生产源码与测试，不留下未检查入口。
- 外部输入（服务端 API 响应、SSE 事件、AI 对话流）以 `unknown` 接收，在边界完成校验与转换后再进入领域层；禁止用类型断言 `as` 代替运行时校验。
- 使用可辨识联合描述组件类型、编排状态、部署阶段与事件种类，避免多个布尔字段产生不可表示或互相矛盾的状态。
- 不使用无说明的 `any`、非空断言 `!` 或强制转换掩盖未知状态；索引访问必须处理缺失值。
- `@ts-ignore`、`@ts-expect-error` 不能用于跳过迁移工作；确需适配外部类型缺陷时，注明触发条件、原因与撤除条件。

## 模块与依赖

- 应用代码采用命名导出，无默认导出；类型专用依赖用 `import type`。
- 按业务能力组织：画布编辑、组件目录、AI 对话、运行状态回显、配置面板各有归属目录；共享模块以具体能力命名，不建 `common/`、`utils/` 堆积目录。
- 领域数据与纯计算（画布投影换算、状态归并）不依赖 React、React Flow、网络客户端与浏览器 API；副作用经注入的服务端口进入。

## React 与 React Flow

- 组件负责渲染与交互，Hook 桥接订阅与生命周期，领域规则与外部 I/O 放在所属模型、服务或适配器。
- **画布是投影，不是真相**：服务端持有已提交画布的期望态真相；前端分离「确认快照 / 待提交操作 / 交互预览」三种状态，React Flow 的节点、边与视口变化经领域用例提交，不直接持久化库对象，不维护第二套可独立写入的业务图。
- 状态单一所有者；确需乐观更新时先说明一致性、失败恢复与过期结果隔离。
- 组件 PascalCase，Hook 用 `useXxx` 命名并在实现前提供中文意图注释；事件处理函数以 `handle` 开头。
- Effect 明确依赖、资源归属与清理；订阅、计时器、SSE 连接与对象 URL 不得在重渲染或 StrictMode 双生命周期中泄漏。
- 异步操作处理卸载、切换画布与乱序完成；请求身份由业务所有者定义，不能只凭组件仍挂载就接受旧结果。
- `memo`、稳定回调解针对已确认的重复渲染；避免每渲染重建节点类型注册表或让全部节点订阅整张图。
- 运行状态回显以服务端事件为源（SSE + 版本序号），断连去重补拉后恢复到服务端状态，不以本地推测冒充运行事实。

## Promise 与错误处理

- 每个 Promise 必须被等待或处理拒绝；只有被调用方拥有内部错误通道时，才可在调用处用 `void` 明确标记有意不等待。
- 不把异步函数直接交给 `() => void` 语义的回调边界；事件入口用同步包装函数启动异步行为，异步所有者负责错误、取消与用户反馈。
- AI 对话与部署流水线这类长任务流：阶段进度、失败与取消对用户始终可见，失败不伪装成空成功；禁用态须表达真实原因。

## 注释与命名

- 文档注释采用 TSDoc 风格：导出的函数、Hook、组件、类型与常量说明意图与契约，带参数或返回值的补全 `@param`、`@returns`；组件 Props 的非常规语义在接口属性注释中说明，默认值用 `@defaultValue` 标注。
- 文件命名：组件 `PascalCase.tsx`，Hook 与工具 `camelCase.ts`，类型文件按领域命名；常量导出用 `SCREAMING_SNAKE_CASE`。
- 禁止提交 `console.log`、未使用导入与未使用变量；诊断走统一 logger 入口（工程初始化时建立）。

## 测试

- 领域与投影换算单测无 React 依赖；组件测试验证真实接线、交互与显示结果；网络与持久化集成测试覆盖真实边界。
- 画布交互的验证矩阵（方向，不代表用例已存在）：拖入组件并提交 → 服务端持久化后投影一致；撤销 → 形成正确历史单元；断连重连 → 恢复服务端状态；切换画布 → 旧请求不写入新会话。
- 不能只对 React Flow 回调的模拟调用做断言，就宣称持久化或状态同步已正确。

## 验证与完成

前端改动运行 `typecheck && lint && test && build`（接入后）；新增源码路径或工具配置时，同步修改真实脚本与根指南范围路由，并在完成报告说明新增检查覆盖的路径。当前无自动检查时如实报告，不把构建成功解释为类型检查或交互验收通过。

提交前遵循[零告警门禁](warning-free-commits.md)：ESLint `--max-warnings 0`、类型检查无错误，Vite / 打包器告警转失败；不能提升警告阈值、关闭规则或静默过滤告警。
