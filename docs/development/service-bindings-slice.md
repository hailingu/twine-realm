# 服务契约与 MySQL 依赖声明（Issue #8）

本切片在 [组件目录](component-catalog-slice.md) 上实现 [Issue #8](https://github.com/hailingu/twine-realm/issues/8) 的服务自有接口、具名端口和数据库依赖声明。连接只保存声明，不建库、创建数据库账号或执行运行操作；用户账号权限仍不在一期范围。

## 定义与兼容

服务先显式提交自己的契约包：ID、版本、配置 JSON Schema、多份具名接口版本及端口。不从仓库名称或 Go 技术栈猜测默认端口。界面的“载入端口示例”是明确的用户动作；示例不代表服务源码已实现这些接口。没有契约的服务保持未就绪草稿，必需消费端口未绑定也允许保存草稿。

每个服务的 ID / 版本内容永久不可改义，SHA-256 根据 Go 规范化 JSON 计算；切换活动版本不解除历史约束。接口可使用不同协议、多个版本；端口固定语义 ID、consume / provide 角色、协议、契约、one / many 基数和是否必需。非 MySQL 端口引用本包的 `interfaceId@version`；数据库端口可声明 MySQL wire 版本，但当前只有 `mysql-wire/10` 与标准 MySQL 提供端口兼容，不隐式转换版本。

每份自有 schema 限于 JSON Schema 2020-12、当前 schema 内片段引用；禁止通过引用读网络、文件或其他 schema。实际 schema 位置的引用由后端核实，业务属性名 `$ref`、注解和示例中的普通数据不误当引用。整个包不超过 32 KiB，接口 / 端口各不超过 20，schema 深度不超过 20、节点数不超过 2048。浏览器只校验包结构，不编译或执行用户 schema；后端使用既有 JSON Schema 编译器最终裁决。

数据库依赖方向是消费服务 → 提供 MySQL，按稳定组件 / 端口身份和两端固定定义引用校验。反向、跨项目、悬空、缺契约 / 端口、角色 / 协议 / 版本不兼容、重复关系或超基数都拒绝。当前每个 MySQL 实例上的数据库名独占一个活动绑定，不隐式共享库；名字使用 1–48 位小写字母、数字和下划线，以字母开头，用途为应用读写或应用只读。

绑定有独立稳定 ID、databaseId 和版本化 credential 引用，不保存真实秘密。重连保留绑定 ID；同一消费服务、MySQL 实例和库名保留 databaseId，同用途也保留凭据引用；改变归属、库名或用途按规则分配新引用。这里的引用只是声明身份，尚没有实际秘密或数据库账号。删除绑定保留退休记录，不删除数据库或卷。

## 原子编辑与 API

新契约在 [graph.schema.json](../../server/contract/v2/graph.schema.json) 和 [OpenAPI v2](../../server/contract/v2/openapi.json)。已发布 v1 的 Project、源码、CanvasState 与各类回执不变；v2 用同一平台库的完整一致快照读取 `project + graph`，graph 包含中间件、服务契约和依赖，没有第二份服务 / 中间件真相。全部编辑与原 v1 共用项目 revision。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v2/projects/{id}/graph` | 同库一致的服务、中间件、契约与绑定快照 |
| `POST /api/v2/projects/{id}/graph/edits` | `{mutationId,baseRevision,operations}`，一次 1–50 个领域操作 |
| `GET /api/v2/graph-mutations/{id}` | 核实原图请求，返回专用 GraphReceipt |

操作为 `service.setContract`、`binding.create`、`binding.reconnect` 和 `binding.remove` 的严格判别联合，不接受任意 JSON patch。先复制候选并应用明确动作，再按最终关系集合裁决端点版本 / 兼容 / 基数；因此同批先建边后声明契约、先加替代边后移除旧边可以成立。更新已有服务契约时，原绑定不会偷偷跟随新版本；须同批显式重连并重新确认端口映射，或移除有关绑定。

原键恢复先于当前图解释；相同请求重放原结果，不因后续图变化重新分配身份。不同意图复用键或 revision 竞争返回冲突。最终声明、不可变契约历史、绑定变化、revision 与规范化回执在同一平台元数据库事务提交；SQL 中途失败全部回滚，无部分图或假成功回执。事务不跨 Git、Docker 或业务数据库。

## 界面与恢复

画布 Handle 的 ID 直接采用具名端口，位置改变不改变语义；动态端口更新后重算节点端点位置。服务消费端为出端，MySQL 提供端为入端，箭头表示依赖关系，标签标明库名和“声明未应用”。React Flow 只投影已确认图，拖线 / 拖动边端点只填候选；用户检查端点、库名和用途后明确保存。检查面板同时提供键盘可用的建立、重连、移除和接口版本映射入口。此适配参考 Infinity Canvas 的具名端口和最终原子校验，未套用媒体 DAG 的方向 / 排序模型。

失败保留当前候选和原关系；发送中或未知结果时冻结交互，核实 / 重试复用原 mutationId。冲突后显式重载完整 v2 图并保留位置与表单候选，再重新确认。旧类源码 / 中间件回执只更新它负责的字段，不能清空已确认契约或连线。布局未保存时先保存或还原，再提交领域编辑。未提交表单仅在当前页面保留，强制刷新可丢失候选；已保存关系跨浏览器和平台重启恢复。

## 验证与边界

Go 单测执行真实 schema 编译；SQL 集成覆盖最终图顺序、并发 / 原键、同版本改义、切走再改历史版本、跨项目真实端点、失败重连及项目范围的受控 SQL CHECK 约束导致的中途回滚。前端执行真实生成校验器，覆盖显式示例、版本映射、原键核实、冲突候选和旧回执兼容。Chromium 执行具名端口拖线、显式确认、重连、移除、丢响应 / 非法角色、双窗口冲突及平台重启恢复；验证源仓库指纹不变。实际通过状态以本次门禁日志和 PR CI 为准。

此处尚无服务配置实例值、业务协议实现验证、真实数据库账号 / 秘密、构建、运行调和或部署。HTTP / 消息调用关系与多个中间件种类在其自己的后续切片发布。源码与声明的一致性由后续固定工程方案 / 构建步骤验证，不能因声明已保存就声称服务可运行。
