# 质量检查与证据

本文定义平台的检查现状、计划接入的门禁与完成证据的口径。**核心原则：报告只列实际运行的命令与真实结果；未配置的检查如实说明，不得虚报、不得臆造命令、不得复用历史绿色结论。**

## 当前状态（2026-11-03）

仓库尚无源码与构建配置，**未配置任何自动检查**。当前所有验证均为结构化评审：核对文档一致性、路径与链接、真实命令描述、适用范围和未完成事项。

## 计划接入的门禁

以下门禁在对应工程初始化任务中接入；接入前它们是目标，不是事实。接入后须同步更新本文、根指南范围路由与相关规范。

| 范围 | 门禁 | 接入时机 |
| --- | --- | --- |
| Go（`server/**`） | `gofmt -l`（零差异）、`go vet ./...`（或 golangci-lint 接入后替代）、`go build ./...`、`go test ./...`（涉并发包加 `-race`） | 初始化 `server/go.mod` 时 |
| TS（`web/**`） | `tsc --noEmit`（严格配置）、ESLint、Vitest、`vite build` | 初始化 `web/package.json` 时 |
| 涉及项目空间编排的功能 | 至少一项经真实 docker-compose 边界的集成验证 | 首个编排切片 |
| compose / 部署文件 | `docker compose config` 校验 | 建立 `deploy/` 时 |

## 证据与报告口径

- 报告包含：实际运行的命令、工作目录、环境版本、结果摘要、未运行项与原因。
- 优先使用稳定证据：提交号、符号、标题、命令输出摘要；可变行号仅作辅助。
- 完成的判定标准：请求的行为、必需的文档、必需的检查与必需的证据全部就绪——而非仅仅完成一次实现尝试。
- 跳过、受阻或失败的检查连同完整原因一并报告；凭据缺失、环境故障不能绕过门禁，如实报告即可。
- 纯文档变更做结构化评审与链接检查，不要求运行源码门禁；混合变更不能按纯文档豁免。

## 禁止事项

- 禁止把目标门禁（如「计划接入 golangci-lint」）描述为已执行。
- 禁止以构建成功替代类型检查、以单测通过替代集成验证、以 mock 调用断言替代真实边界结果。
- 禁止为通过检查降低断言强度（删除边界场景、放宽超时、更换更轻替身）后宣称问题解决。
