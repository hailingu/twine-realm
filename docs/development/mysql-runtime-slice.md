# 本机 MySQL 运行与恢复（Issue #12）

本页定义 [Issue #12](https://github.com/hailingu/twine-realm/issues/12) 的实现边界，在[组件目录切片](component-catalog-slice.md)上增加真实运行。功能、检查存在不等于本次验收已通过；提交、PR、当前 head 的 CI、合并与 Project 状态分别核实。

## 支持范围

原生 Mac / Linux 控制面进程，通过本地 Unix socket Docker context 和 Compose 插件管理每项目一个固定 MySQL 组件。Compose 至少 2.24；镜像必须预先缓存目录锁定的 `mysql:9.7.4@sha256:df90258da46f6e7ff8574ff84f17618aba0765cac749928299c69fd4e7cb8ad8`，不隐式拉取。具体 Compose、daemon 与镜像内容身份在初始化时固定，每次执行或采集重新核实。

每实例拥有安装 / 项目 / 组件 / 资源 / 配置摘要标签、独立 IPv4 内部 bridge 网络、命名数据卷和固定容器。3306 / 33060 均不发布到宿主；平台就绪检查通过容器内固定客户端、文件凭据和真实认证查询完成，不能用 TCP 或进程存在代替。初始化临时 MySQL 进程不算就绪，最终 PID 1 必须是 `mysqld`，版本和 `server_uuid` 都须核实。

Mac Docker Desktop 的 `inspect` 可能以 `/host_mnt` 加规范宿主路径表示绑定来源。仅在 Mac 控制面、已核实的 Docker Desktop daemon 及安装清单固定为 `desktop-host-mnt-v1` 时，识别该确定映射；原路径其余部分、类型、目的地、只读性仍须完全一致。普通 Linux daemon 仅接受原来源路径；环境映射模式改变会阻断接续。网络只接受固定 IPv4 / 禁用 IPv6 参数，额外驱动选项拒绝。容器还核实镜像内容、命令、环境、权限、内存、网络、端口、卷、秘密挂载与认证探针，不凭同名或标签单独接管。

首次运行锁定定义、配置和资源身份。后续配置修改仍是画布声明，不偷偷重建数据库；运行按钮明确提示配置差异并阻止使用另一配置。停止使用原实例，不因新声明非法而失去停止入口。配置升级、多个 MySQL 实例、自定义镜像、远程 Docker、容器化控制面、k8s、业务账号 / 迁移 / 连接注入、业务构建部署、AI、SSE、删除数据和备份恢复不属于此切片。平台账号 / 登录 / 配对 / RBAC 仍不开发或接入。

## 显式启用与文件凭据边界

默认不启用执行器，仍能读取已有运行记录与最后事实。先按[根 README](../../README.md)准备平台库、依赖和 `TWINE_REPOSITORY_ROOTS`；在同一个可信终端完成：

```bash
go -C server build -o ../build/runtime-init ./cmd/runtime-init
./build/runtime-init --directory '/Users/you/Library/Application Support/twine-realm/runtime'
export TWINE_RUNTIME_ADAPTER=file-secrets-v1
export TWINE_RUNTIME_DIRECTORY='/Users/you/Library/Application Support/twine-realm/runtime'
./build/platform
```

路径仅为示例，父目录须已存在，运行根本身必须是不存在的新目录。初始化仅核实环境并创建私有文件，不创建容器。运行根必须在业务仓库允许范围、平台 Git 工作区和静态文件目录之外，也不能是包含这些目录的宽泛根。根与子目录 0700、普通文件 0600，均属于当前 UID；拒绝根本身或内部材料的符号链接、FIFO、特殊文件及含插值字符的规范路径，不替用户修改既有目录权限。终端中已设 `DOCKER_HOST` / `DOCKER_CONTEXT` / `DOCKER_CONFIG` 会明确拒绝，先核实并由使用者清除这些覆盖后再使用明确记录的 context。

`file-secrets-v1` 是用户明确选择的本机明文文件适配器，只受当前 OS 用户和文件权限保护，**不宣称加密、Keychain 或多用户隔离，也不从其他秘密库静默降级**。根包含安装清单、项目锁、每资源的 root 密码文件、客户端选项、秘密版本证据和固定 Compose 材料。密码随机生成，只作为只读文件挂载；Docker argv / 环境值、元数据库、HTTP、画布及诊断不包含密码。元数据库只保存不透明秘密引用。数据库 root 用于本切片初始化与认证探针，不是平台用户账号系统。

禁止范围尚未创建时，先规范化其最近已存在父目录再比较；不能让 `/var` 等父目录别名绕过未来仓库范围。无法解析的链接明确阻塞，无关未来目录仍可保留；不为此创建或改写禁止目录。

首次准备秘密先于创建数据卷；已有密码从不覆盖。卷曾经登记存在后，原卷、秘密或秘密版本证据缺失 / 改变，均进入需核实状态，禁止生成新密码或创建空卷冒充恢复。普通停止保留全部秘密与卷。迁移私有根、替换 daemon、切换安装身份、轮换密码和导入外来数据库没有自动入口；须先恢复原环境与材料并核实，不能仅改元数据绕过。

## 同库受理与独立版本

机器契约为 [runtime.schema.json](../../server/contract/v1/runtime.schema.json)，由原 v1 入口显式关联。Go 和前端只注册发布的本地分片与内置配置 schema，禁止联网解析任意引用。原项目、画布与源码回执保持原义。

| 概念 | 所有者与含义 |
| --- | --- |
| 画布 `revision` | 服务端已保存声明 / 布局的并发版本；保存配置不会运行 |
| 目标 `generation` | 独立运行意图版本；受理时固定目标 ID、画布 revision、配置、资源和动作 |
| 操作 `version` / 执行代次 | 可变操作进度及每次持久领取的围栏；不会改变原目标 |
| 项目事件 `sequence` | 独立递增的可分页进展游标，不冒充画布版本 |
| `observedAt` / 新鲜度 | 真正采集时间；未知保留最后事实，20 秒过期，不以操作 succeeded 维持绿色 |

接受目标时，画布 revision、固定实例、目标代次、原请求身份、操作与步骤、事件和不可变受理回执在同一平台元数据库事务内核实 / 提交。提交未知返回未知结果，不发出下一 Docker 步骤；事务内不调用 Docker。运行模块使用同库独立的 `runtime_schema_migrations` 历史，避免占用其他切片的核心迁移版本；启动会先完成核心和运行模块迁移，任一失败都不开放 HTTP。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/runtime/capabilities` | 是否显式启用、固定镜像与 Compose 版本；不是数据库健康 |
| `GET /api/v1/projects/{id}/runtime` | 同库当前目标、操作 / 步骤、最后事实与新鲜度 |
| `POST /api/v1/projects/{id}/runtime/{componentId}/targets` | `{mutationId,baseRevision,baseGeneration,desired,retryOf?}`，202 仅表示持久受理 |
| `GET /api/v1/runtime-mutations/{id}` | 原请求固定回执；不会重跑或重开终态操作 |
| `GET /api/v1/projects/{id}/runtime/operations/{operationId}` | 原操作与步骤，被新目标替代后仍可查 |
| `GET /api/v1/projects/{id}/runtime/events?after=0` | 每页最多 100 条的 MySQL 领域审计，显式读取下一页；全项目 SSE 独立使用 v5 游标 |

原键同内容返回同一目标与操作，同键异内容冲突。前端未知结果只核实或重试原路由 / 原命令，双击不能产生第二个目标。只有收到原回执并读取至少对应代次的确认快照，才解除受理保护。刷新页面可从服务端快照及操作的原请求 ID 找回已受理目标；未送达请求的页面内身份不写浏览器长期存储，强制关闭页面后不能凭空证明是否送达。关闭浏览器不会取消后台已受理操作。

## 执行、恢复与漂移

运行按预检 → 秘密与固定材料 → 私网 → 数据卷 → 容器 → 认证就绪推进；停止按预检 → 停止归属容器 → 核实停止推进。每个外部步骤之前持久登记执行中，核实同一资源后才登记成功。容器首次创建使用固定材料和 `--no-recreate --pull never`；未知结果先检查原资源，不改名生成第二实例。

持久执行租约 180 秒，单次执行期限 165 秒，就绪等待最多 120 秒。租约到期不等于旧进程退出，因此同项目还持有跨进程文件锁覆盖外部 I/O；锁文件不删除，避免 inode 分裂。每次领取递增执行代次；每个步骤及就绪等待都检查当前目标 / 执行代次。新目标替代旧任务后，旧外部结果可保留到原步骤，不能发布为新目标成功；新执行获得锁后重新核实现场。

暂时错误初次加最多 5 次重试，1–30 秒退避并抖动，耗尽保留原错误码并进入 `needs_attention`。控制面退出将原执行结算为待恢复；来不及结算时，重启按过期租约检查原实例。`accepted` / `executing` / `waiting_retry` 是持续执行状态；`succeeded` / `needs_attention` / `failed` / `superseded` 不由同键重放重新执行。明确修复后接受新请求，`retryOf` 记录原操作。

控制面每约 5 秒有界轮转采集，网页经 [v5 一致状态与 SSE](project-state-slice.md)回显，能力和外部候选核实保留有界读取；多项目或工具阻塞时采集会延后，以新鲜度诚实呈现。采样失败不更新旧事实的采集时间，按实际时间比较不同小数精度的 RFC3339，迟到旧采样连同其诊断一起丢弃。原 `server_uuid` 只首次确认，外部替换不会覆盖它。成功结算必须有近期认证就绪或实际停止事实。

已成功目标后，外部手动停止、删除、改名、改配置或换库只上报未知 / 漂移 / 需核实，不自动重建或重新启动。用户明确接受新的运行目标才可恢复原实例。平台 `Ctrl-C` 退出不会停止 MySQL；使用详情「确认停止 MySQL」接受独立停止目标。停止不会删除源码、卷、网络、秘密或数据。本切片没有物理删除 API。

## 验证与证据

根 `npm run test:platform` 新建随机密码的临时平台库、全新运行安装身份及私有根，运行真实 Compose / MySQL / Chromium、控制面重启、SQL 迁移 / 回滚 / 并发 / 旧执行围栏和 `-race`。协议替身仅证明外部边界拒绝、清理失败传播与故障分类，不代替实际容器认证、数据见证和重启证明。前端单测覆盖版本回退、原键恢复、矛盾响应、卸载与读取失败，告警识别还验证 React 重复 key / 缺 key 告警会导致门禁失败。

测试清理与产品停止分开：清理所有者只使用启动测试时冻结的新安装身份，重新核实相同 daemon、完整标签和实际资源 ID 后，删除本次临时资源。daemon 改变、外来对象、工具告警或结果未知时保留资源及绑定文件并返回失败，报告保留位置；上层门禁不能在此时删除运行根。历史迁移测试仅在独占临时数据库中先回退运行模块，再构造旧核心版本，随后按核心 → 运行模块顺序恢复，不关闭外键或强行清除 dirty 标记。

普通预览与真实用户数据不被测试使用或清理。完整零告警、依赖审计和 Sonar 要求仍按[质量检查](quality-gates.md)执行，具体通过 / 失败和分析 ID 由本次交付证据说明。
