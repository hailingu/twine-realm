# 问题记录规范

本平台的缺陷、功能、技术债与评审意见统一记录在仓库根目录 `issues/` 本地目录，不向外部平台创建或同步。

## 文件与命名

- 每个问题一个文件：`ISSUE-NNNN-中文简述.md`（如 `ISSUE-0001-画布期望态存储选型.md`）。
- 编号四位递增，全仓唯一，不复用已删除记录的编号。

## 文件头字段

```markdown
# ISSUE-NNNN：<标题>

- 编号：ISSUE-NNNN
- 状态：open | accepted | fixed | deferred | wontfix
- 严重性：blocker | major | minor | debt
- 创建日期：YYYY-MM-DD
- 关联：<相关文件、设计章节、提交号，可空>

## 问题描述
<触发条件、影响与证据（测试、日志、命令输出）>

## 验收标准
- <可观察、可验证的关闭条件>

## 处置记录
- YYYY-MM-DD：<决策、变更与验证；关闭时写明关闭证据（提交号/命令结果）>
```

## 规则

- 状态流转必须留处置记录；未完成或仅记录边界的工作不得描述为已修复。
- 关闭证据用稳定引用：提交号、命令结果摘要、验证说明；不以「应该没问题」关闭。
- 严重性按真实影响评估，不凭假想极值放大范围；已确认的问题不得以「防御性建议」略过。
- 例外采用（如规范豁免）在对应 issue 记录规则、原因、风险、补偿验证与复查条件。
