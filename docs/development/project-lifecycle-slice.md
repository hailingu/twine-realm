# 项目保留数据停止与恢复切片

对应 [Issue #20](https://github.com/hailingu/twine-realm/issues/20)。本文件先记录实现前的状态矩阵与验收约束；完成实际检查前，不代表功能已验收。

## 范围与所有权

一期只管理既有单个 Go/net/http 服务和原 MySQL。持久父操作直接拥有步骤、租约和外部动作账本，不虚构组件租约或修改历史成功操作。原源码、候选、物理计划、容器、网络、卷、UUID、秘密和业务数据必须保持；缺失时失败关闭，不创建替代资源，不清除 dirty 或盲重跑迁移。无账号、RBAC、平台部署与跨 Docker/数据库事务。

## 状态与不变量矩阵

| 前置状态 | 动作顺序 | 可观察结果 | 不变量与所有者 | 验证 |
| --- | --- | --- | --- | --- |
| 原服务和 MySQL 均已成功且完整核实 | 冻结目标并受理父停止，先应用后数据库 | 两端停止，原资源保留 | 父账本拥有顺序，项目行锁拥有受理和许可 | 真实 CRUD 停止、另一项目与元数据库不受影响 |
| 已核实停止，无未结外部动作 | 原数据库启动、认证及 UUID 核实，再原应用启动和完整性/HTTP 核实 | 恢复同一业务数据 | 严格适配器不补建材料、容器、卷或角色 | 原资源身份、固定候选、数据恢复 |
| 受理响应丢失 | 查询原键、重放同键 | 唯一回执与操作 | 回执与父目标、通知同事务 | 重复请求和网络丢失测试 |
| 步骤间控制面重启 | 领取已知持久边界 | 延续同一操作 | 操作/执行代次围栏 | 重启恢复测试 |
| Docker 命令在途时失联或进程退出 | 持久未知结果 | 明确未知且阻断不安全反向动作 | inspect 一次或经过时间不能证明旧命令不会晚到 | 真实取消及迟到测试 |
| 旧观察者在父代次改变后完成 | 尝试写回旧结果 | 拒绝覆盖新状态 | observation epoch 随父转换推进 | 迟到观察并发测试 |
| 原材料、秘密或物理资源缺失/替换 | 严格核实 | 保留现场并显示阻塞/偏差 | 不接管外来对象、不重建 | 缺失、归属冲突与外部变更测试 |
| 稳定恢复后用户显式操作组件 | 正常组件动作 | 显示当前偏差 | 父成功是历史事实，不永久自动调和 | 正常许可恢复测试 |

## 协议与完成边界

v1–v5 严格契约保持不变；v6 完整状态必须在同一 RR 元数据事务读取。SSE 仅使界面核实完整状态，不确认 mutation，也不拥有命令取消。停止事实的采集时间与以前的认证、迁移证明分别展示。父结算、相关有效观察及通知同事务完成。

验收按纯状态、真实元数据库、严格适配器、真实业务 CRUD 和浏览器顺序开展，随后完整零告警门禁、Sonar、真实 pre-commit、准确 PR head CI 与全部评审。测试仅使用并清理其自有隔离资源。实际命令、结果、未运行项和限制在完成时补充，不复用旧绿色结果。

## 接口与恢复

v6 增加以下独立入口，v5 事件仍只负责通知失效：

- `GET /api/v6/projects/{id}/state`：同一 RR 事务返回原 v5 状态及父生命周期。
- `POST /api/v6/projects/{id}/lifecycle`：以 `mutationId`、`baseRevision`、`baseGeneration` 和 `desired` 接受停止或恢复。
- `GET /api/v6/projects/{id}/lifecycle/receipts/{mutationId}`：核实原请求回执，不执行命令。
- `POST /api/v6/projects/{id}/lifecycle/receipts/{mutationId}/retry`：显式接续已知安全失败的原操作，不创建新目标；未知外部动作拒绝重试。

前端按项目在 sessionStorage 保存非敏感原命令，刷新后先用严格契约验证并核实原键。SSE 不清除未知命令；只有明确回执或明确拒绝才清除。停止后的普通组件动作被父许可阻断；稳定恢复后允许用户显式组件操作并展示偏差。

父动作账本先提交 executing，再执行 Docker，最后登记 succeeded。客户端取消、进程丢失或结果无法持久化都不能证明守护进程动作撤销。已知步骤边界可接续；存在 executing/unknown 时不重复执行或放行逆向动作。外部未知必须保留现场，当前切片不提供强制清账入口。

独立观察令牌在父受理、结算和重试时推进；普通观察在父执行或停止期间不得覆盖父事实。停止事实保留独立时间，不把旧认证或迁移证明改成新的成功证明。
