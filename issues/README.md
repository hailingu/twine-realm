# 本地问题目录

项目问题统一在本目录创建和维护，使用中文 Markdown，不向外部问题平台创建或同步。完整要求见 [问题记录规范](../docs/development/issue-standard.md)。

## 创建与编号

1. 先搜索现有记录，确认问题未被登记；一个问题一份文件，不创建无事实依据的占位缺陷。
2. 从 [_template.md](_template.md) 复制为 `ISSUE-0001-中文短名.md`，按已有最大编号递增，禁止重用编号。
3. 填写文件头，按缺陷、功能、工程债务或已知边界裁剪正文，补齐可验证的验收标准。
4. 创建后再次检查编号冲突；发现并发重复时重新分配本次新编号并修正链接，不能覆盖已有记录。

稳定编号是文件头的 `id`，文件名和编号在后续状态变化中保持不变。记录可按编号检索，不强制维护一份易过时的手工状态汇总。

## 元数据与生命周期

文件头字段：`id`、`title`、`type`、`status`、`priority`、`scope`、`createdAt`、`updatedAt`；可选 `owner`。标题形如 `P2(server): 节点交互问题摘要`，`priority` 与标题一致。

| 字段 | 可用值 |
| --- | --- |
| `type` | 缺陷、功能、工程债务、已知边界 |
| `status` | 待处理、进行中、待验证、已关闭、暂缓 |
| `priority` | P1、P2、P3 |
| `scope` | server、web、deploy、design、docs、tooling；跨域记录用 `+` 联写（如 `server+web`） |

正常流程为「待处理 → 进行中 → 待验证 → 已关闭」。需要延期时设为「暂缓」并记录触发条件、风险和恢复条件；复发时重新打开原记录或关联新的独立问题，保留历史处置。

每次状态变化更新 `updatedAt` 和处置记录。关闭前逐项确认验收，记录真实命令、结果、修订与已知限制；不把本地关闭写成代码已提交、已推送或已部署。

编号仍从现有最大编号人工递增分配，没有自动编号器。元数据与状态由仓库根 `npm run issue:status` 自动校验：文件头必填字段、type/status/priority/scope 枚举、编号与文件名一致且唯一、日期格式及 `updatedAt` 不早于创建日期和最后处置记录；候选 `ISSUE-*.md` 文件名不合规时报错，处置日期支持正文、括号说明和日期标题，且只读取「处置记录」章节，忽略其他章节及代码示例。该命令同时输出状态统计与未关闭清单（`--json` 为结构化摘要），未关闭是正常工作流状态，仅元数据或文件名违规才非零退出。验收与证据质量仍采用结构化评审及链接核对。模板不是实际问题记录，不占用编号；当前目录尚无记录，守卫在首条记录出现后开始约束数量。
