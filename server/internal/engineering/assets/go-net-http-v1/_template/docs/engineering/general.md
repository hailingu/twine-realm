# 业务通用工程规范 1.0.0

适用于此服务的生产代码、测试和工程配置。规则来源及平台 / 业务映射见 [sources.json](sources.json)。本文件为受控适用版本快照，离线可完整读取；升级需明确差异、范围和接受记录，不跟随上游在线文档自动变化。

| 规则 | 要求 | 验证 |
| --- | --- | --- |
| GEN-01 职责 | 按业务能力组织模块，依赖经明确构造注入；领域不依赖 HTTP、SQL 或运行平台对象；禁止循环依赖与公共杂物模块 | 依赖编译及人工结构审阅 |
| GEN-02 规模 | 生产文件不超过 800 行、测试不超过 1800 行，超过 600 / 1000 先审阅；函数不超过 80 代码行，超过 60 先审阅；不靠机械搬行伪造职责 | 人工规模 / 职责审阅，静态复杂度 |
| GEN-03 说明 | 新模块、公共类型 / 函数有中文意图注释，说明契约与清理责任；失败不可静默吞掉，不提交未使用项 | go vet、编译及人工审阅 |
| GEN-04 状态 | 实现前记录重要状态、顺序、可观察结果和不变量；失败、取消、并发、未知结果分别处理，副作用有明确提交屏障 | 行为与真实依赖测试 |
| GEN-05 资源 | 每个 goroutine、连接、文件、事务与监听器有所有者和关闭路径；事务内不执行远程 I/O | 竞态、生命周期测试及审阅 |
| GEN-06 信任 | 外部 JSON / 配置 / 驱动结果先校验；密码只从获准文件读取，不进入源码、日志、API、构建或错误文本 | 输入、文件、泄露负例与角色验证 |
| GEN-07 证据 | 人工与 AI 使用同一检查入口；缺工具、失败、未运行、人工项不冒称通过；可复现缺陷先提供失败证据 | 真实命令结果与审阅 |
| GEN-08 变更 | 保留人工工作与项目现有规则。不得通过排除源码、关闭检查、降低级别或改写规范消除失败；例外需具体范围、理由、补偿及接受记录 | 差异审阅 |

平台的画布、React、仓库工具、控制面数据库、Project 状态及特定 Git 分支命名不适用于本服务。业务服务自己的授权、契约、规范与兼容要求仍须同时满足；无法解决的冲突阻塞相关开发和交付。

自动检查不能证明领域模型、完整安全或全部业务正确性。必需人工审阅项包括职责、状态 / 数据迁移影响、业务契约、权限和例外；文档读取成功也不能证明 agents 已理解或满足全部条款。
